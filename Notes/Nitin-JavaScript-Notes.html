Chapter 0: Contents

Chapter 1: Variables & Data Types

1. Overview

A variable is a named box that stores a value. We use variables to keep test data like user names, URLs and status codes. Every value has a data type, like string, number or boolean, and typeof tells us that type.

2. Core Concepts

2.1 let

We use let when the value will change later. It is block scoped, so it lives only inside its { }.

let userName = "Amit";
console.log(userName); // Amit

userName = "Neha";
console.log(userName); // Neha

let status = "pass";
if (true) {
  let status = "fail";
  console.log(status); // fail
}
console.log(status); // pass

2.2 const

We use const when the value should not be reassigned. It must get a value at the time of declaration.

const baseUrl = "https://test.example.com";
console.log(baseUrl); // https://test.example.com

baseUrl = "https://prod.example.com";

Output

TypeError: Assignment to constant variable.

With a const object, we cannot reassign the variable, but we can change its properties.

const user = { name: "Amit", age: 25 };
user.age = 26;
console.log(user); // { name: 'Amit', age: 26 }

2.3 var

var is the old way. It is function scoped, not block scoped. It can be declared again, and it is hoisted with the value undefined. In modern code we use let and const.

var browser = "chrome";
var browser = "firefox";
console.log(browser); // firefox

if (true) {
  var city = "Delhi";
}
console.log(city); // Delhi

Same idea with let gives an error outside the block.

if (true) {
  let town = "Pune";
}
console.log(town);

Output

ReferenceError: town is not defined

Hoisting: var gives undefined before its line, let gives an error.

console.log(count); // undefined
var count = 5;

console.log(total);
let total = 10;

Output

undefined
ReferenceError: Cannot access 'total' before initialization

2.4 string

A string is text. We can write it with double quotes, single quotes or backticks.

const firstName = "Amit";
const lastName = 'Sharma';
const course = `JavaScript`;
console.log(firstName, lastName, course); // Amit Sharma JavaScript

2.5 number

Whole numbers and decimals are both of type number. Special values are Infinity and NaN (Not a Number).

const statusCode = 200;
const price = 99.5;
console.log(statusCode + 1); // 201
console.log(price);          // 99.5
console.log(10 / 0);         // Infinity
console.log("abc" * 2);      // NaN

2.6 boolean

A boolean has only two values: true or false. It is used for checks and conditions.

const isLoggedIn = true;
const isAdmin = false;
console.log(isLoggedIn); // true
console.log(5 > 3);      // true

2.7 null

null means "no value" and we set it on purpose.

let selectedCourse = null;
console.log(selectedCourse); // null

2.8 undefined

undefined means a value was never given. JavaScript sets it automatically.

let token;
console.log(token); // undefined

const student = { name: "Amit" };
console.log(student.age); // undefined

2.9 typeof

typeof returns the type of a value as a string. Note: typeof null is "object", an old bug in JavaScript.

console.log(typeof "Amit");      // string
console.log(typeof 200);         // number
console.log(typeof true);        // boolean
console.log(typeof undefined);   // undefined
console.log(typeof null);        // object
console.log(typeof { id: 1 });   // object
console.log(typeof [1, 2]);      // object
console.log(typeof NaN);         // number

3. Interview Questions and Answers

Q1. What is the difference between var, let and const?

var is function scoped, can be declared again with the same name, and is hoisted with the value undefined. let and const are block scoped, which means they live only inside the nearest { }.

let allows reassignment, while const does not. A const must also get a value at the time it is declared. In modern code, const is the default choice and let is used only when the value must change.

Q2. What is hoisting?

Hoisting means JavaScript moves declarations to the top of their scope before the code runs. Only the declaration moves, not the value.

With var, reading the variable before its line gives undefined. With let and const, reading it early throws ReferenceError: Cannot access 'total' before initialization.

Q3. What is the Temporal Dead Zone?

The Temporal Dead Zone is the time between the start of a block and the line where a let or const variable is declared. The variable exists, but it cannot be used yet.

Any access in this zone throws a ReferenceError. This makes bugs easier to catch than with var, which silently gives undefined.

Q4. Can a const object be changed?

Yes, its properties can be changed. const only stops reassignment of the variable itself, not changes inside the object.

So user.age = 26 works fine, but user = {} throws TypeError: Assignment to constant variable. The same rule applies to arrays, so push works on a const array.

Q5. What are the data types in JavaScript?

JavaScript has seven primitive types: string, number, bigint, boolean, undefined, null and symbol. Primitive means a simple single value.

Everything else is an object, including arrays and functions. In daily test automation work, string, number, boolean, null, undefined and object are used the most.

Q6. What is the difference between null and undefined?

undefined means a variable was declared but never given a value. JavaScript sets it automatically, for example for let token; or a missing object property.

null means "empty on purpose". A developer sets it to show that there is no value right now. Also, typeof undefined is "undefined", while typeof null is "object".

Q7. Why does typeof null return "object"?

This is an old bug from the first version of JavaScript. It was never fixed because fixing it would break many existing websites.

So null is still a primitive type, even though typeof says "object". To check for null, a direct check like value === null is used.

Q8. What is block scope?

Block scope means a variable is available only inside the { } where it is declared, like inside an if or a loop.

let and const follow block scope. var does not, so a var declared inside an if block is still visible outside it.

Q9. Can let and var be declared again with the same name?

var can be declared again in the same scope without any error. The new value simply replaces the old one, which can hide bugs.

let and const cannot be declared twice in the same scope. Doing so gives SyntaxError: Identifier 'a' has already been declared.

Q10. What happens if a const is declared without a value?

It is a syntax error. The code does not run at all and Node.js shows SyntaxError: Missing initializer in const declaration.

This happens because a const can never be assigned later, so it must get its value on the same line.

Q11. What does typeof return?

typeof returns the type of a value as a string, like "string", "number", "boolean", "undefined", "object" or "function".

It is useful for checking data before using it, for example checking that an API field is a number. For arrays it returns "object", so Array.isArray() is used to check an array.

Q12. What is NaN and what is its type?

NaN means "Not a Number". It comes from a math operation that fails, like "abc" * 2.

Even though the name says "not a number", typeof NaN returns "number". To check for it, Number.isNaN(value) is used.

Q13. Is JavaScript statically typed or dynamically typed?

JavaScript is dynamically typed. The type belongs to the value, not to the variable, and it is checked while the code runs.

So the same let variable can hold a string first and a number later. This is flexible but can cause bugs, and that is one reason TypeScript is popular.

Q14. Which one should be used by default: var, let or const?

const should be the default. It makes the code safer because the value cannot be reassigned by mistake.

let is used when the value must change, like a counter or a retry count. var is avoided in modern code because of its function scope and hoisting behavior.

Q15. What is the difference between single quotes, double quotes and backticks?

Single and double quotes work the same way. Both create a normal string, and the choice is mostly team style.

Backticks create a template literal. It allows putting variables inside with ${ } and writing strings on many lines.

Q16. What happens when an undeclared variable is used?

Reading a variable that was never declared throws an error like ReferenceError: town is not defined.

One special case is typeof. typeof notDeclared does not throw an error and simply returns "undefined".

Q17. Are integers and decimals different types in JavaScript?

No. Both whole numbers like 200 and decimals like 99.5 are of type number.

Because of how decimals are stored, small rounding issues can appear, for example 0.1 + 0.2 gives 0.30000000000000004. For very large whole numbers, the separate bigint type is used.

Chapter 2: Strings

1. Overview

A string is text, like a user name, an email or a page title. In testing we build strings, clean them and check them all the time. JavaScript gives us many built-in string methods for this work.

2. Core Concepts

2.1 Concatenation

We join strings with the + operator. If one side is a string, the other side is turned into a string too.

const firstName = "Amit";
const lastName = "Sharma";
console.log(firstName + " " + lastName); // Amit Sharma
console.log("Status: " + 200);           // Status: 200
console.log("5" + 5);                    // 55
console.log(5 + 5 + "5");                // 105
console.log("Total: " + 5 + 5);          // Total: 55
console.log("Total: " + (5 + 5));        // Total: 10

2.2 Template Literals

Template literals use backticks. We put variables or expressions inside ${ }. They also support many lines.

const name = "Amit";
const course = "JavaScript";
const marks = 85;
console.log(`${name} scored ${marks} in ${course}`); // Amit scored 85 in JavaScript
console.log(`Total: ${10 + 5}`);                     // Total: 15

const msg = `Line 1
Line 2`;
console.log(msg);

Output

Amit scored 85 in JavaScript
Total: 15
Line 1
Line 2

2.3 length

length is a property, not a method, so we do not use (). It gives the number of characters. Spaces also count.

console.log("Amit".length);     // 4
console.log("Hello QA".length); // 8
console.log("".length);         // 0
console.log("Amit"[0]);         // A
console.log("Amit"[10]);        // undefined

2.4 includes()

includes() checks if a string contains some text. It returns true or false and it is case sensitive.

const title = "Login successful";
console.log(title.includes("success")); // true
console.log(title.includes("Success")); // false

2.5 trim()

trim() removes spaces from both ends. trimStart() and trimEnd() remove from one side only.

const input = "   amit@test.com  ";
console.log(input.trim());                   // amit@test.com
console.log(input.trim().length);            // 13
console.log("[" + input.trimStart() + "]");  // [amit@test.com  ]
console.log("[" + input.trimEnd() + "]");    // [   amit@test.com]

2.6 split()

split() breaks a string into an array using a separator.

const browsers = "chrome,firefox,safari";
console.log(browsers.split(","));       // [ 'chrome', 'firefox', 'safari' ]
console.log("Amit Sharma".split(" "));  // [ 'Amit', 'Sharma' ]
console.log("abc".split(""));           // [ 'a', 'b', 'c' ]
console.log("abc".split(","));          // [ 'abc' ]

2.7 replace()

replace() changes only the first match. replaceAll() changes every match.

const text = "Order failed. Payment failed.";
console.log(text.replace("failed", "passed"));    // Order passed. Payment failed.
console.log(text.replaceAll("failed", "passed")); // Order passed. Payment passed.
console.log("$10.00".replace("$", ""));           // 10.00

2.8 slice()

slice(start, end) returns a part of the string. The end index is not included. Negative numbers count from the end.

const id = "USER-12345";
console.log(id.slice(5));      // 12345
console.log(id.slice(0, 4));   // USER
console.log(id.slice(-3));     // 345
console.log(id.slice(-5, -2)); // 123

2.9 toLowerCase() and toUpperCase()

These change the letter case. They are useful for case-insensitive checks.

console.log("Hello QA".toLowerCase()); // hello qa
console.log("Hello QA".toUpperCase()); // HELLO QA
console.log("Pass".toLowerCase() === "PASS".toLowerCase()); // true

2.10 Strings Do Not Change

Strings are immutable. Methods return a new string and the original stays the same. We can chain methods.

const status = "test";
console.log(status.toUpperCase(), status); // TEST test

const role = "  Admin User  ";
console.log(role.trim().toLowerCase().replace(" ", "_")); // admin_user

3. Interview Questions and Answers

Q1. What is the difference between concatenation and template literals?

Concatenation joins strings with the + operator, like "Hello " + name. It works, but with many variables it becomes long and hard to read.

Template literals use backticks and put values inside ${ }, like `Hello ${name}`. They are cleaner, can run expressions such as ${10 + 5}, and support strings on many lines without special characters.

Q2. Are strings mutable in JavaScript?

No, strings are immutable. Once a string is created, its characters cannot be changed. Writing status[0] = "b" does nothing.

Methods like toUpperCase() or replace() always return a new string. To keep the result, it must be stored in a variable.

Q3. What is the difference between replace() and replaceAll()?

replace() changes only the first match when a string is passed as the search value. replaceAll() changes every match.

For example, on "Order failed. Payment failed.", replace("failed", "passed") changes only the first word, while replaceAll changes both.

Q4. What is the result of "5" + 5 and 5 + 5 + "5"?

"5" + 5 gives "55". When one side of + is a string, the number is turned into a string and both are joined.

5 + 5 + "5" gives "105". The code runs left to right, so 5 + 5 becomes 10 first, and then "5" is joined to it.

Q5. How can a case-insensitive string check be done?

Both strings are changed to the same case first, using toLowerCase() or toUpperCase(), and then compared.

For example, "Pass".toLowerCase() === "PASS".toLowerCase() gives true. The same idea works with includes(), which is case sensitive by default.

Q6. Is length a method or a property?

length is a property, so it is written without brackets, like "Amit".length, which gives 4.

It counts every character, including spaces. An empty string has a length of 0. It is often used to check that a field is not empty.

Q7. How does slice() work with negative numbers?

slice(start, end) returns the part from start up to, but not including, end. If end is missing, it goes to the end of the string.

Negative numbers count from the end. So "USER-12345".slice(-3) gives "345". This is handy for getting the last digits of an ID or order number.

Q8. What does split() return?

split() always returns an array. It cuts the string wherever the separator is found, like "chrome,firefox".split(",") giving [ 'chrome', 'firefox' ].

If the separator is not found, the array has one item, the full string. Using an empty string "" as separator splits it into single characters.

Q9. Why is trim() important in test automation?

Text taken from a web page or a file often has extra spaces or new lines at the start or end. A direct compare with the expected value would then fail.

trim() removes this whitespace from both ends, so the check compares only the real text. It does not remove spaces in the middle of the string.

Q10. Is includes() case sensitive?

Yes. "Login successful".includes("Success") gives false because the capital S does not match.

To ignore case, both values are changed to lower case first, like title.toLowerCase().includes("success").

Q11. What happens when a character index outside the string is accessed?

Using square brackets like "Amit"[10] returns undefined. No error is thrown.

Indexes start from 0, so the last character is at length - 1. The at(-1) method can also be used to get the last character directly.

Q12. What is method chaining with strings?

Method chaining means calling one method right after another on the same line. Each method returns a new string, so the next method works on that result.

For example, " Admin User ".trim().toLowerCase().replace(" ", "_") gives "admin_user". It keeps the code short, but very long chains can be harder to debug.

Q13. What is the difference between single quotes, double quotes and backticks?

Single and double quotes create the same normal string. The choice usually depends on team style or on which quote appears inside the text.

Backticks create template literals. Only backticks support ${ } for values and strings that go over many lines.

Q14. How can a value like "$10.00" be turned into clean text?

replace("$", "") removes the dollar sign and gives "10.00". For many symbols or commas, replaceAll() is used.

The result is still a string. It can then be turned into a number for math checks, like comparing a cart total.

Q15. What do trimStart() and trimEnd() do?

trimStart() removes whitespace only from the beginning of a string. trimEnd() removes it only from the end.

They are useful when spaces on one side matter and should be kept, while trim() cleans both sides at once.

Chapter 3: Operators

1. Overview

Operators are symbols that do work on values, like adding, comparing or checking conditions. In testing we use them to compare actual and expected results, check status codes and give default values. Using the right operator avoids many hidden bugs.

2. Core Concepts

2.1 Arithmetic Operators

We use + - * / % ** for math. % gives the remainder and ** is power.

console.log(10 + 3);  // 13
console.log(10 - 3);  // 7
console.log(10 * 3);  // 30
console.log(10 / 4);  // 2.5
console.log(10 % 3);  // 1
console.log(2 ** 3);  // 8

We can also increase, decrease and update a value in short form.

let count = 5;
count++;
console.log(count); // 6
count--;
console.log(count); // 5

let total = 100;
total += 50;
console.log(total); // 150
total -= 20;
console.log(total); // 130

+ with a string joins text. Other math operators turn the string into a number.

console.log("10" + 2); // 102
console.log("10" - 2); // 8
console.log("10" * 2); // 20

2.2 Comparison Operators

Comparison operators return true or false.

console.log(200 > 100); // true
console.log(5 >= 5);    // true
console.log(3 < 1);     // false
console.log(4 <= 4);    // true

2.3 == vs ===

== (loose equality) changes types before comparing. === (strict equality) checks value and type both. We always prefer === and !==.

console.log(5 == "5");           // true
console.log(5 === "5");          // false
console.log(0 == false);         // true
console.log(0 === false);        // false
console.log(null == undefined);  // true
console.log(null === undefined); // false
console.log(5 !== "5");          // true
console.log(NaN === NaN);        // false

2.4 Logical Operators (&&, ||, !)

&& is true only if both sides are true. || is true if one side is true. ! flips the value.

const isLoggedIn = true;
const isAdmin = false;
console.log(isLoggedIn && isAdmin); // false
console.log(isLoggedIn || isAdmin); // true
console.log(!isAdmin);              // true

With non-boolean values, && and || return one of the values, not just true or false. Falsy values are false, 0, "", null, undefined and NaN.

console.log("" || "Guest");      // Guest
console.log(0 || 10);            // 10
console.log("Amit" && "Neha");   // Neha
console.log(null && "Amit");     // null
console.log(!!"Amit");           // true
console.log(!!"");               // false

2.5 Ternary Operator

The ternary operator is a short if/else on one line: condition ? valueIfTrue : valueIfFalse.

const statusCode = 200;
const result = statusCode === 200 ? "Pass" : "Fail";
console.log(result); // Pass

const marks = 45;
console.log(marks >= 50 ? "Passed" : "Failed"); // Failed

2.6 Optional Chaining (?.)

?. safely reads a property. If the value before it is null or undefined, it returns undefined instead of throwing an error.

const user = { name: "Amit", address: { city: "Delhi" } };
console.log(user.address?.city);  // Delhi
console.log(user.contact?.phone); // undefined

const users = [];
console.log(users[0]?.name);      // undefined

console.log(user.contact.phone);

Output

Delhi
undefined
undefined
TypeError: Cannot read properties of undefined (reading 'phone')

2.7 Nullish Coalescing (??)

?? gives a default value only when the left side is null or undefined. || gives the default for any falsy value, like 0 or "".

let timeout = 0;
console.log(timeout || 30000); // 30000
console.log(timeout ?? 30000); // 0

let token = null;
console.log(token ?? "default"); // default

const user = { name: "Amit" };
console.log(user.contact?.phone ?? "No phone"); // No phone

3. Interview Questions and Answers

Q1. What is the difference between == and ===?

== is loose equality. It changes the types of both values to match before comparing, so 5 == "5" is true. This hidden type change is called type coercion.

=== is strict equality. It checks both value and type, so 5 === "5" is false. === is the safer choice and is used in almost all modern code and test checks.

Q2. What is the difference between || and ???

|| returns the right side when the left side is any falsy value, such as 0, "", false, null or undefined.

?? returns the right side only when the left side is null or undefined. So with timeout = 0, timeout || 30000 gives 30000, but timeout ?? 30000 keeps 0. ?? is better when 0 or an empty string is a valid value.

Q3. What is optional chaining and why is it useful?

Optional chaining is the ?. operator. It stops and returns undefined if the value before it is null or undefined, instead of throwing a TypeError.

It is very useful with API responses, where some nested fields may be missing. For example, response.data?.user?.email does not crash even if data is missing.

Q4. What are truthy and falsy values?

Falsy values act like false in a condition. They are false, 0, "", null, undefined and NaN.

Every other value is truthy, including "0", "false", empty arrays [] and empty objects {}. This matters because ||, && and if all use these rules.

Q5. What do && and || return when used with non-boolean values?

They return one of the actual values, not always true or false. || returns the first truthy value, or the last value if none is truthy. So "" || "Guest" gives "Guest".

&& returns the first falsy value, or the last value if all are truthy. So "Amit" && "Neha" gives "Neha" and null && "Amit" gives null.

Q6. What is the ternary operator?

The ternary operator is a short way to write if/else in one line. The format is condition ? valueIfTrue : valueIfFalse.

For example, statusCode === 200 ? "Pass" : "Fail" returns "Pass" for a 200 code. It is good for simple choices, but nested ternaries become hard to read.

Q7. What is the result of "10" + 2 and "10" - 2?

"10" + 2 gives "102", because + with a string joins text.

"10" - 2 gives 8, because - only works with numbers, so the string is turned into a number first. The same happens with * and /.

Q8. Why is NaN === NaN false?

NaN means "Not a Number", and by rule it is not equal to anything, not even itself. So both NaN == NaN and NaN === NaN give false.

To check for it, Number.isNaN(value) is used. This is helpful when a price or count taken from a page fails to convert into a number.

Q9. What does the % operator do?

% is the remainder operator. It gives what is left after division, so 10 % 3 is 1.

A common use is checking even or odd numbers, like num % 2 === 0. It is also used to repeat something every few steps, like every third row in a table.

Q10. What is the result of null == undefined and null === undefined?

null == undefined is true. Loose equality treats both as "no value" and considers them equal.

null === undefined is false because they are different types. This is one more reason strict equality is preferred.

Q11. What does the ! operator do and what is !!?

! is the NOT operator. It flips a value, so !true is false. It first turns any value into a boolean based on truthy and falsy rules.

!! is simply two NOT operators. It turns any value into its real boolean form, so !!"Amit" is true and !!"" is false.

Q12. What is short-circuit evaluation?

Short-circuit means JavaScript stops checking as soon as the result is known. With &&, if the left side is falsy, the right side is never run.

With ||, if the left side is truthy, the right side is skipped. This allows patterns like isLoggedIn && showDashboard(), where the function runs only if the user is logged in.

Q13. Can optional chaining and nullish coalescing be used together?

Yes, and this is a very common pattern. ?. safely reads a property that may be missing, and ?? gives a default value when the result is null or undefined.

For example, user.contact?.phone ?? "No phone" returns "No phone" when there is no contact. It keeps the code short and safe with API data.

Q14. What do ++, --, += and -= do?

++ adds 1 to a variable and -- removes 1. They are common in counters, like counting passed tests.

+= and -= are short forms. total += 50 means total = total + 50. These only work with let, not const, because they change the value.

Q15. What does the ** operator do?

** is the power operator. 2 ** 3 means 2 × 2 × 2, which gives 8.

It does the same work as Math.pow(2, 3) but is shorter. A simple use is building a wait time that grows on each retry.

Chapter 4: Conditions

1. Overview

Conditions let our code take different paths based on a check. We use if, else if, else and switch to decide what runs. In testing we use them to check status codes, roles, browsers and environments.

2. Core Concepts

2.1 if

The code inside if runs only when the condition is true.

const statusCode = 200;
if (statusCode === 200) {
  console.log("Request passed"); // Request passed
}

2.2 if / else

else runs when the if condition is false.

const isLoggedIn = false;
if (isLoggedIn) {
  console.log("Show dashboard");
} else {
  console.log("Show login page"); // Show login page
}

2.3 if / else if / else

We use else if to check many conditions in order. The first true one runs and the rest are skipped.

const marks = 72;
if (marks >= 90) {
  console.log("Grade A");
} else if (marks >= 70) {
  console.log("Grade B"); // Grade B
} else if (marks >= 50) {
  console.log("Grade C");
} else {
  console.log("Fail");
}

2.4 Conditions with Logical Operators

We can join checks with && and ||.

const role = "admin";
const isActive = true;
if (role === "admin" && isActive) {
  console.log("Full access"); // Full access
}

2.5 Truthy and Falsy in Conditions

if works with any value. Empty string, 0, null, undefined and NaN are treated as false. An empty array is truthy, so we check its length.

const userName = "";
if (userName) {
  console.log("Hello " + userName);
} else {
  console.log("Name is empty"); // Name is empty
}

const items = [];
if (items.length === 0) {
  console.log("Cart is empty"); // Cart is empty
}

2.6 switch

switch compares one value with many case values. break stops it. default runs when no case matches.

const browser = "firefox";
switch (browser) {
  case "chrome":
    console.log("Launch Chrome");
    break;
  case "firefox":
    console.log("Launch Firefox"); // Launch Firefox
    break;
  default:
    console.log("Unknown browser");
}

2.7 switch without break (Fall-through)

If we forget break, code keeps running into the next cases.

const code = 404;
switch (code) {
  case 200:
    console.log("OK");
  case 404:
    console.log("Not Found");
  case 500:
    console.log("Server Error");
  default:
    console.log("Unknown");
}

Output

Not Found
Server Error
Unknown

2.8 Grouping Cases

We can put many cases together to run the same code.

const env = "staging";
switch (env) {
  case "dev":
  case "staging":
    console.log("Test environment"); // Test environment
    break;
  case "prod":
    console.log("Live environment");
    break;
}

2.9 switch Uses Strict Comparison

switch compares with ===, so the type must match too.

const value = "5";
switch (value) {
  case 5:
    console.log("Number 5");
    break;
  default:
    console.log("No match"); // No match
}

3. Interview Questions and Answers

Q1. What is the difference between if/else and switch?

if/else can check any kind of condition, like ranges (marks >= 70), many variables, or logical operators. It is the more flexible choice.

switch compares one value against many fixed values, like browser names or status codes. When there are many exact matches, switch is often cleaner and easier to read.

Q2. What happens if break is missing in a switch case?

Without break, the code "falls through". After a matching case runs, all the cases below it also run, until a break or the end of the switch.

For example, matching 404 without breaks prints "Not Found", "Server Error" and "Unknown". This is a common bug, but it can be used on purpose to group cases.

Q3. Does switch use == or ===?

switch uses strict comparison, which is the same as ===. Both value and type must match.

So a string "5" does not match case 5:. This often causes bugs when a value comes from a page or a URL as a string, but the cases are numbers.

Q4. What is the role of default in switch?

default runs when no case matches. It works like the final else in an if/else chain.

It is optional, but good practice, because it handles unexpected values, like an unknown browser name. It is usually written last, though JavaScript allows it anywhere.

Q5. How does else if work, and does order matter?

JavaScript checks each condition from top to bottom. The first condition that is true runs, and all the rest are skipped.

So order matters a lot. If marks >= 50 is checked before marks >= 90, a score of 95 would get the wrong grade. The strictest check should come first.

Q6. What values are treated as false in an if condition?

The falsy values are false, 0, "" (empty string), null, undefined and NaN. All of them make an if skip its block.

Everything else is truthy, including "0", [] and {}. So an empty array still passes an if, and items.length === 0 is used to check if it is empty.

Q7. How can many cases share the same code in switch?

Cases can be written one after another without code or break between them. They all fall through to the same block.

For example, case "dev": and case "staging": written together both print "Test environment". This avoids repeating the same code.

Q8. When is the ternary operator better than if/else?

The ternary operator is better for a simple choice that returns a value, like const result = code === 200 ? "Pass" : "Fail". It fits on one line.

if/else is better when there are many lines of code, many conditions, or actions instead of values. Nested ternaries are hard to read and are best avoided.

Q9. Can curly braces be skipped in an if statement?

Yes. If there is only one statement, braces can be left out, like if (age >= 18) console.log("Adult");.

It is still safer to always use braces. If a second line is added later without braces, it will run every time, not only when the condition is true.

Q10. How can a range of values be checked with switch?

A trick called switch (true) is used. Each case holds a condition, like case score >= 90:, and the first case that is true runs.

It works, but most teams find if/else if clearer for ranges. switch is mainly meant for exact values.

Q11. How are many conditions combined in one if?

&& is used when all conditions must be true, like role === "admin" && isActive. || is used when any one condition is enough.

Brackets can group checks to make the logic clear, like (a || b) && c. Long conditions can also be stored in well-named variables first, which improves readability.

Q12. What is a nested if, and how can it be avoided?

A nested if is an if inside another if. A few levels are fine, but deep nesting makes code hard to read and test.

It can be reduced by combining checks with &&, using else if, or using an early return inside functions to exit as soon as a check fails.

Q13. Why is === preferred inside if conditions?

=== checks both value and type, so there are no hidden type changes. statusCode === 200 is true only for the number 200.

With ==, values like 0 == false or "" == 0 become true, which can make a test pass or fail by mistake.

Q14. Is the default case required to be last in switch?

No. default can be placed anywhere, and it still runs only when no case matches. Its position just affects fall-through if break is missing.

By convention it is placed last, because that is easiest to read and understand.

Chapter 5: Loops

1. Overview

A loop runs the same block of code again and again. We use loops to go through lists of users, test data, status codes or browsers. Loops save us from writing the same line many times.

2. Core Concepts

2.1 for Loop

The for loop has three parts: start, condition and update. We use it when we know how many times to run.

for (let i = 1; i <= 3; i++) {
  console.log("Test run " + i);
}

Output

Test run 1
Test run 2
Test run 3

2.2 while Loop

The while loop runs as long as the condition is true. We use it when we do not know the exact count, like retry logic.

let attempt = 1;
while (attempt <= 3) {
  console.log(`Login attempt ${attempt}`);
  attempt++;
}

Output

Login attempt 1
Login attempt 2
Login attempt 3

2.3 for...of Loop

for...of gives us each value of an array or string. It is the cleanest way to loop over a list.

const browsers = ["chrome", "firefox", "webkit"];
for (const browser of browsers) {
  console.log(browser);
}

for (const ch of "QA") console.log(ch);

Output

chrome
firefox
webkit
Q
A

2.4 for...in Loop

for...in gives us each key of an object. We read the value with obj[key].

const user = { name: "Amit", role: "tester", active: true };
for (const key in user) {
  console.log(key + ": " + user[key]);
}

Output

name: Amit
role: tester
active: true

2.5 forEach

forEach is an array method. It calls a function for each item and gives the value and the index. It always returns undefined.

const codes = [200, 404, 500];
codes.forEach((code, index) => {
  console.log(index, code);
});

const result = codes.forEach((c) => c);
console.log(result); // undefined

Output

0 200
1 404
2 500
undefined

2.6 break

break stops the loop fully. Here we stop as soon as we find a server error.

const statuses = [200, 200, 500, 200];
for (const status of statuses) {
  if (status === 500) {
    console.log("Server error found");
    break;
  }
  console.log("OK:", status);
}

Output

OK: 200
OK: 200
Server error found

2.7 continue

continue skips only the current round and moves to the next one. Here we skip empty names.

const students = ["Riya", "", "Karan"];
for (const name of students) {
  if (name === "") {
    continue;
  }
  console.log("Student:", name);
}

Output

Student: Riya
Student: Karan

3. Interview Questions and Answers

Q1. What is a loop and why is it used in test automation?

A loop is a block of code that runs many times until a condition stops it. It removes repeated code and keeps scripts short.

In test automation, loops are used to run the same test with many data sets, check every item in a list, check many status codes, or retry an action until it passes.

Q2. What is the difference between a for loop and a while loop?

A for loop is used when the number of rounds is known. The start, condition and update are all written in one line, like for (let i = 0; i < 5; i++).

A while loop is used when the number of rounds is not known. It keeps running while a condition is true, for example retrying an API call until the status is 200.

Q3. What is the difference between for...of and for...in?

for...of gives the values. It works on iterable things like arrays, strings, Maps and Sets. "Iterable" simply means something that can be walked through one item at a time.

for...in gives the keys (property names). It is mainly used for plain objects. On an array, it gives the indexes as strings, not the values.

Q4. Why is for...in not recommended for arrays?

With an array, for...in gives the indexes as strings like "0", "1", not numbers. Doing math on them can give wrong results, for example "0" + 1 becomes "01".

It can also pick up extra properties added to the array. For arrays, for...of, a normal for loop or forEach is the safer choice.

Q5. Can for...of be used directly on a plain object?

No. A plain object is not iterable, so for...of throws an error. For an object named course, the error is TypeError: course is not iterable.

To loop over an object, for...in can be used. Another way is for...of with Object.keys(), Object.values() or Object.entries(), because these return arrays.

Q6. What is forEach and what does it return?

forEach is an array method that runs a function once for each item. The function gets the value, the index and the full array.

It always returns undefined. So it is used only to do something with each item, like logging or checking. To build a new array, map is used instead.

Q7. Can break or continue be used inside forEach?

No. break inside a forEach callback gives SyntaxError: Illegal break statement. continue also gives a syntax error. The callback is a separate function, so these keywords do not belong to any loop there.

A return inside the callback only skips the current item, like continue. There is no simple way to stop forEach early, so for...of or a normal for loop is used when stopping early is needed.

Q8. What is the difference between break and continue?

break stops the whole loop at once. The code after the loop runs next.

continue skips only the current round. The loop moves on to the next item. For example, break is used to stop at the first failed test, and continue is used to skip empty test data.

Q9. Which loops support break and continue?

break and continue work in for, while, for...of and for...in loops.

They do not work in forEach, because forEach is a method that calls a function, not a real loop statement.

Q10. What is an infinite loop and how can it be avoided?

An infinite loop is a loop whose condition never becomes false, so it never stops. A common reason is forgetting to update the counter, like missing attempt++ in a while loop.

It can be avoided by always updating the variable used in the condition and by adding a maximum limit, like tries < 3. This is very important in retry logic, so a test does not hang forever.

Q11. Does forEach wait for async/await?

No. forEach does not wait for an async callback. It starts all the calls and moves on at once, so the code after it runs before the work is done.

When each step must finish before the next one, like API calls in order, for...of with await is used. It waits for each item one by one.

Q12. How can each character of a string be read using a loop?

The easiest way is for...of, because a string is iterable. Each round gives one character.

A normal for loop also works, using str[i] and str.length. This is useful when the index is also needed.

Q13. How can the index be read inside a for...of loop?

for...of gives only values by default. To get the index too, array.entries() is used, like for (const [i, b] of browsers.entries()). Each round gives the index and the value together.

Another option is forEach, which gives the index as the second argument, or a normal for loop with i.

Q14. How can keys and values of an object be read in a loop?

for...in gives each key, and the value is read with user[key].

Another clean way is for (const [key, value] of Object.entries(user)). Object.entries() returns an array of key-value pairs, so for...of can loop over it.

Q15. How can a while loop be used for retry logic in a test?

A while loop keeps trying an action until it passes or a limit is reached. The condition usually checks two things, like status !== 200 && tries < 3.

Inside the loop, the counter goes up and the action runs again. The limit makes sure the test does not run forever if the server never responds correctly.

Q16. What is the output of this code?

let sum = 0;
for (let i = 1; i <= 5; i++) {
  sum += i;
}
console.log(sum);

Output

15

The loop runs for i = 1, 2, 3, 4 and 5. Each round adds i to sum, so the total is 1 + 2 + 3 + 4 + 5 = 15.

console.log is outside the loop, so it prints only once, after the loop ends.

Q17. What is the output of this code with var and let inside setTimeout?

for (var i = 0; i < 3; i++) {
  setTimeout(() => console.log(i), 100);
}
for (let j = 0; j < 3; j++) {
  setTimeout(() => console.log(j), 200);
}

Output

3   (after 100 ms)
3
3
0   (after 200 ms)
1
2

With var, there is only one i shared by all rounds. The timers run after the loop ends, when i is already 3, so 3 is printed three times.

With let, each round gets its own new j. Each timer remembers its own value, so 0, 1 and 2 are printed.

Q18. What is the output of this code using continue?

for (let i = 1; i <= 6; i++) {
  if (i % 2 === 0) continue;
  console.log(i);
}

Output

1
3
5

i % 2 === 0 is true for even numbers. For 2, 4 and 6, continue skips the console.log and the loop moves to the next number.

Only the odd numbers 1, 3 and 5 reach the console.log line.

Q19. What is the output of this for...in loop on an array?

const arr = [10, 20, 30];
for (const i in arr) {
  console.log(i + 1);
}

Output

01
11
21

for...in gives array indexes as strings: "0", "1", "2". Adding a number to a string joins them as text, so "0" + 1 becomes "01".

The values 10, 20 and 30 are never used. This is the main reason for...of is preferred for arrays.

Q20. What is the output of this code that reverses a string?

const word = "login";
let reversed = "";
for (const ch of word) {
  reversed = ch + reversed;
}
console.log(reversed);

Output

nigol

for...of reads one character at a time: l, o, g, i, n. Each new character is added in front of the old text, not after it.

So the text grows as "l", "ol", "gol", "igol", "nigol". The final result is the word in reverse order.

Chapter 6: Arrays

1. Overview

An array is an ordered list of values stored in one variable. We use arrays to keep lists of users, browsers, status codes or test results. Array methods help us add, remove, search, change and total these values easily.

2. Core Concepts

2.1 Array Basics

We create an array with square brackets. Indexes start at 0. length gives the number of items. A missing index gives undefined.

const browsers = ["chrome", "firefox", "webkit"];
console.log(browsers[0]);      // chrome
console.log(browsers.length);  // 3
console.log(browsers[5]);      // undefined

const mixed = [1, "two", true, null];
console.log(mixed);            // [ 1, 'two', true, null ]
console.log(typeof browsers, Array.isArray(browsers)); // object true

2.2 push()

push adds items at the end. It changes the array and returns the new length.

const users = ["Amit"];
const newLen = users.push("Riya", "Karan");
console.log(users);   // [ 'Amit', 'Riya', 'Karan' ]
console.log(newLen);  // 3

2.3 pop()

pop removes the last item and returns it. On an empty array it returns undefined.

const steps = ["open", "login", "logout"];
const last = steps.pop();
console.log(last);      // logout
console.log(steps);     // [ 'open', 'login' ]
console.log([].pop());  // undefined

2.4 map()

map runs a function on each item and returns a new array of the same length. The original array does not change.

const marks = [40, 55, 70];
const updated = marks.map((m) => m + 5);
console.log(updated);  // [ 45, 60, 75 ]
console.log(marks);    // [ 40, 55, 70 ]

const names = ["amit", "riya"].map((n) => n.toUpperCase());
console.log(names);    // [ 'AMIT', 'RIYA' ]

2.5 filter()

filter returns a new array with only the items that pass the condition. If nothing matches, it returns an empty array.

const codes = [200, 404, 201, 500];
const ok = codes.filter((c) => c < 300);
console.log(ok);                            // [ 200, 201 ]
console.log(codes.filter((c) => c > 600));  // []

2.6 find()

find returns the first item that matches. If nothing matches, it returns undefined.

const students = [
  { id: 1, name: "Amit" },
  { id: 2, name: "Riya" },
];
console.log(students.find((s) => s.id === 2));  // { id: 2, name: 'Riya' }
console.log(students.find((s) => s.id === 9));  // undefined

2.7 some() and every()

some returns true if at least one item matches. every returns true only if all items match.

const results = ["pass", "fail", "pass"];
console.log(results.some((r) => r === "fail"));   // true
console.log(results.every((r) => r === "pass"));  // false

console.log([].every((r) => r === "pass"));  // true
console.log([].some((r) => r === "pass"));   // false

2.8 includes()

includes checks if a value is in the array. It returns true or false. It is case-sensitive.

const roles = ["admin", "tester"];
console.log(roles.includes("tester"));  // true
console.log(roles.includes("Admin"));   // false

2.9 sort()

sort changes the original array. By default it sorts as text, so numbers need a compare function.

const fruits = ["mango", "apple", "banana"];
fruits.sort();
console.log(fruits);  // [ 'apple', 'banana', 'mango' ]

const nums = [10, 1, 5, 100];
console.log([...nums].sort());                  // [ 1, 10, 100, 5 ]
console.log([...nums].sort((a, b) => a - b));   // [ 1, 5, 10, 100 ]
console.log([...nums].sort((a, b) => b - a));   // [ 100, 10, 5, 1 ]

2.10 slice()

slice(start, end) returns a copy of a part of the array. The end index is not included. The original array does not change.

const tests = ["t1", "t2", "t3", "t4"];
console.log(tests.slice(1, 3));  // [ 't2', 't3' ]
console.log(tests.slice(-2));    // [ 't3', 't4' ]
console.log(tests);              // [ 't1', 't2', 't3', 't4' ]

2.11 splice()

splice(start, count, ...newItems) removes and/or adds items. It changes the original array and returns the removed items.

const items = ["a", "b", "c", "d"];
const removed = items.splice(1, 2);
console.log(removed);  // [ 'b', 'c' ]
console.log(items);    // [ 'a', 'd' ]

items.splice(1, 0, "x", "y");
console.log(items);    // [ 'a', 'x', 'y', 'd' ]

2.12 reduce()

reduce turns the whole array into one value, like a total. It takes a function and a starting value.

const prices = [100, 250, 50];
const total = prices.reduce((sum, p) => sum + p, 0);
console.log(total);  // 400

3. Interview Questions and Answers

Q1. What is an array in JavaScript?

An array is an ordered list of values stored in one variable. Each value has an index, and the index starts at 0. The length property gives the number of items.

An array can hold any type of value, like numbers, strings, booleans and objects, even mixed together. In test automation, arrays are used for lists of test data, users, browsers and status codes.

Q2. How can it be checked that a value is an array?

typeof is not helpful here, because typeof [] returns "object". Arrays are a special kind of object in JavaScript.

The correct way is Array.isArray(value). It returns true for arrays and false for everything else.

Q3. What do push() and pop() return?

push adds one or more items at the end of the array and returns the new length, not the array.

pop removes the last item and returns that removed item. If the array is empty, pop returns undefined. Both methods change the original array.

Q4. What is the difference between map() and forEach()?

map returns a new array with the result of the function for each item. The new array always has the same length as the original.

forEach only runs the function and returns undefined. So map is used to build a new list, and forEach is used just to do something with each item, like logging.

Q5. What is the difference between map() and filter()?

map changes each item and returns a new array of the same length. For example, it can turn all names into uppercase.

filter does not change items. It only keeps the items that pass a condition, so the new array can be shorter. For example, it can keep only passed tests.

Q6. What is the difference between find() and filter()?

find returns only the first matching item, not an array. If nothing matches, it returns undefined. It also stops as soon as it finds a match.

filter returns an array of all matching items. If nothing matches, it returns an empty array []. find is used to get one user by id, and filter is used to get all failed tests.

Q7. What is the difference between some() and every()?

some returns true if at least one item passes the condition. every returns true only if all items pass.

On an empty array, some returns false and every returns true. In tests, every is useful to check that all results are "pass", and some is useful to check if any test failed.

Q8. How does includes() work?

includes checks if an array contains a given value and returns true or false. It uses strict comparison, so the type must also match.

It is case-sensitive for strings. So ["admin"].includes("Admin") returns false. It is commonly used to check if a role, status code or browser name is in an allowed list.

Q9. Why does sort() give wrong results for numbers?

By default, sort changes the values into strings and compares them as text. So "100" comes before "5", because the character "1" comes before "5".

To sort numbers correctly, a compare function is passed. (a, b) => a - b sorts in ascending order, and (a, b) => b - a sorts in descending order.

Q10. Does sort() change the original array?

Yes. sort sorts the array in place, which means the original array itself changes. It also returns the same array, not a new one.

To keep the original safe, a copy is sorted instead, like [...nums].sort(). The spread ... makes a new shallow copy first.

Q11. What is the difference between slice() and splice()?

slice(start, end) returns a copy of part of the array. The end index is not included, and the original array does not change.

splice(start, count, ...items) removes and/or adds items in the original array. It changes the array and returns the removed items as a new array.

Q12. Which array methods change the original array and which do not?

Methods that change the original array are called mutating methods. From this chapter, these are push, pop, sort and splice.

Methods that do not change it are map, filter, find, some, every, includes, slice and reduce. They return a new value and leave the original as it is.

Q13. How does reduce() work?

reduce goes through the array and builds one final value. The function gets an accumulator, which is the running result, and the current item. Whatever the function returns becomes the new accumulator.

The second argument is the starting value, like 0 for a sum or {} for counting. It is used for totals, maximum values, counting items and grouping data.

Q14. Why should an initial value be given to reduce()?

Without an initial value, reduce uses the first item as the start. On an empty array, there is no first item, so it throws TypeError: Reduce of empty array with no initial value.

Giving an initial value, like 0, makes the code safe for empty arrays. It also makes the type of the result clear.

Q15. Why does map() sometimes return an array of undefined?

This happens when an arrow function uses curly braces but has no return. For example, [1, 2, 3].map((n) => { n * 2; }) gives [ undefined, undefined, undefined ].

With curly braces, return must be written. Without curly braces, like (n) => n * 2, the value is returned automatically.

Q16. What is the output of this sort code?

const nums = [10, 1, 5, 100];
console.log([...nums].sort());
console.log([...nums].sort((a, b) => a - b));

Output

[ 1, 10, 100, 5 ]
[ 1, 5, 10, 100 ]

The first sort has no compare function, so it compares values as text. As text, "1", "10" and "100" all start with "1", so they come before "5".

The second sort uses a - b. A negative result puts a first, so the numbers are sorted in real number order.

Q17. What is the output of this slice and splice code?

const arr = [1, 2, 3, 4, 5];
console.log(arr.slice(1, 3));
console.log(arr.splice(1, 3));
console.log(arr);

Output

[ 2, 3 ]
[ 2, 3, 4 ]
[ 1, 5 ]

slice(1, 3) takes items from index 1 up to index 3, but not including 3. So it returns [ 2, 3 ], and arr stays the same.

splice(1, 3) starts at index 1 and removes 3 items: 2, 3 and 4. It returns them, and arr is left with only [ 1, 5 ].

Q18. What is the output when one array is assigned to another variable?

const a = [1, 2, 3];
const b = a;
b.push(4);
console.log(a);
console.log(a === b);

Output

[ 1, 2, 3, 4 ]
true

const b = a does not make a copy. Both variables point to the same array in memory. This is called a reference.

So b.push(4) also changes a, and a === b is true. To make a real copy, [...a] or a.slice() is used.

Q19. What is the output of this code that counts test results?

const results = ["pass", "fail", "pass", "skip", "pass"];
const count = results.reduce((acc, r) => {
  acc[r] = (acc[r] || 0) + 1;
  return acc;
}, {});
console.log(count);

Output

{ pass: 3, fail: 1, skip: 1 }

The starting value is an empty object {}. For each result, the code reads the current count, or 0 if the key is not there yet, and adds 1.

"pass" appears three times, "fail" once and "skip" once. The keys appear in the order they were first added.

Q20. What is the output of this map, filter and reduce chain?

const total = [1, 2, 3]
  .map((n) => n * 2)
  .filter((n) => n > 2)
  .reduce((sum, n) => sum + n, 0);
console.log(total);

Output

10

map doubles each number, giving [ 2, 4, 6 ]. Then filter keeps only numbers greater than 2, giving [ 4, 6 ].

Finally, reduce adds them starting from 0: 0 + 4 + 6 = 10. Each method returns a new array, so the methods can be chained one after another.

Chapter 7: Objects

1. Overview

An object stores data as key-value pairs inside curly braces. We use objects to keep related data together, like a user, a test config or an API response. Destructuring, spread and rest help us read, copy and merge objects easily.

2. Core Concepts

2.1 Object Basics

We read a value with dot notation or bracket notation. A missing key gives undefined. We can add, update and delete keys at any time.

const user = { name: "Amit", age: 25, active: true };
console.log(user.name);     // Amit
console.log(user["age"]);   // 25
console.log(user.email);    // undefined

user.email = "amit@test.com";  // add
user.age = 26;                 // update
delete user.active;            // delete
console.log(user);  // { name: 'Amit', age: 26, email: 'amit@test.com' }

2.2 Bracket Notation, "in" and Nested Objects

Bracket notation is used when the key is stored in a variable. The in operator checks if a key exists. Objects can also hold other objects.

const user = { name: "Amit", email: "amit@test.com" };
const key = "name";
console.log(user[key]);          // Amit
console.log("email" in user);    // true

const student = { name: "Riya", address: { city: "Pune" } };
console.log(student.address.city);  // Pune
console.log(student);  // { name: 'Riya', address: { city: 'Pune' } }

2.3 Object.keys()

Object.keys returns an array of all keys. Its length tells us how many keys there are, or if the object is empty.

const config = { browser: "chrome", headless: true, retries: 2 };
console.log(Object.keys(config));         // [ 'browser', 'headless', 'retries' ]
console.log(Object.keys(config).length);  // 3
console.log(Object.keys({}).length === 0);  // true

2.4 Object.values()

Object.values returns an array of all values.

const config = { browser: "chrome", headless: true, retries: 2 };
console.log(Object.values(config));  // [ 'chrome', true, 2 ]

2.5 Object.entries()

Object.entries returns an array of [key, value] pairs. It works well with for...of.

const config = { browser: "chrome", headless: true, retries: 2 };
console.log(Object.entries(config));

for (const [key, value] of Object.entries(config)) {
  console.log(`${key} = ${value}`);
}

Output

[ [ 'browser', 'chrome' ], [ 'headless', true ], [ 'retries', 2 ] ]
browser = chrome
headless = true
retries = 2

2.6 Object Destructuring

Destructuring takes values out of an object into variables in one line. We can rename a variable, give a default value, and read nested values.

const res = { status: 200, body: { id: 7, name: "Amit" } };

const { status, body } = res;
console.log(status, body);      // 200 { id: 7, name: 'Amit' }

const { status: code, message = "OK" } = res;
console.log(code, message);     // 200 OK

const { body: { id } } = res;
console.log(id);                // 7

2.7 Array Destructuring and Destructuring in Parameters

Arrays are destructured by position. A function can also destructure the object passed to it.

const [first, second] = ["chrome", "firefox", "webkit"];
console.log(first, second);  // chrome firefox

function login({ username, password }) {
  return `${username} / ${password}`;
}
console.log(login({ username: "amit", password: "secret" }));  // amit / secret

2.8 Spread Operator (...)

Spread copies all keys of an object into a new object. Later keys overwrite earlier keys. The original stays the same. It works on arrays too.

const base = { browser: "chrome", headless: true };
const ci = { ...base, headless: false, retries: 2 };
console.log(ci);    // { browser: 'chrome', headless: false, retries: 2 }
console.log(base);  // { browser: 'chrome', headless: true }

const arr = [...[1, 2], 3];
console.log(arr);   // [ 1, 2, 3 ]

2.9 Rest Operator (...)

Rest collects the "remaining" items into one object or array. We use it to remove a key, or to accept any number of function arguments.

const testUser = { name: "Amit", password: "secret", role: "tester" };
const { password, ...safeUser } = testUser;
console.log(safeUser);  // { name: 'Amit', role: 'tester' }

const [head, ...others] = ["t1", "t2", "t3"];
console.log(head, others);  // t1 [ 't2', 't3' ]

function total(...nums) {
  return nums.reduce((sum, n) => sum + n, 0);
}
console.log(total(10, 20, 30));  // 60

3. Interview Questions and Answers

Q1. What is an object in JavaScript?

An object is a collection of key-value pairs written inside curly braces. Each key is a name, and each value can be any type, like a string, number, array, function or another object.

Objects keep related data together in one place. In test automation, objects are used for test users, config settings, API request bodies and API responses.

Q2. What is the difference between dot notation and bracket notation?

Dot notation, like user.name, is short and clean. It is used when the key name is known and is a simple word.

Bracket notation, like user["name"], takes a string. It is needed when the key is stored in a variable, like user[key], or when the key has spaces or dashes, like headers["content-type"].

Q3. What happens when a key that does not exist is read?

Reading a missing key does not throw an error. It simply returns undefined.

But reading a key inside a missing nested object throws an error. For example, if address is missing, user.address.city throws TypeError: Cannot read properties of undefined (reading 'city').

Q4. If an object is declared with const, can its values be changed?

Yes. const only stops the variable from being given a new value. It does not lock the object itself.

So keys can still be added, updated and deleted. But writing user = {} again gives an error, because that tries to reassign the variable.

Q5. How can a key be added, updated or removed?

A key is added or updated with simple assignment, like user.email = "a@test.com". If the key exists, its value is replaced. If not, a new key is created.

A key is removed with the delete keyword, like delete user.active. After that, reading the key gives undefined.

Q6. How can it be checked if a key exists in an object?

The in operator is used, like "email" in user. It returns true or false.

Checking user.email !== undefined also works in most cases. But in is more correct, because a key can exist and still have the value undefined.

Q7. What is the difference between Object.keys(), Object.values() and Object.entries()?

Object.keys returns an array of keys. Object.values returns an array of values. Object.entries returns an array of [key, value] pairs.

All three return normal arrays. So array methods like map, filter and reduce, and loops like for...of, can be used on the result.

Q8. How can it be checked if an object is empty?

The common way is Object.keys(obj).length === 0. If the object has no keys, the array is empty, so the length is 0.

Checking obj === {} does not work. Two objects are compared by reference, not by content, so this is always false.

Q9. How can an object be looped over?

One way is for...in, which gives each key. The value is read with obj[key].

Another clean way is for (const [key, value] of Object.entries(obj)). This gives both the key and the value in each round. for...of cannot be used directly on a plain object, because a plain object is not iterable.

Q10. What is object destructuring?

Destructuring is a short way to take values out of an object into variables. For example, const { status, body } = res creates two variables from the response object.

The variable name must match the key name. If a key is missing, the variable becomes undefined. It is very common for reading API responses and function options.

Q11. How can a variable be renamed and given a default value in destructuring?

A colon renames the variable. const { status: code } = res reads the status key but stores it in a variable named code.

An equals sign gives a default value. const { message = "OK" } = res uses "OK" only when message is missing or undefined. Both can be used together.

Q12. What is the spread operator and how is it used with objects?

The spread operator ... copies all keys from one object into a new object. It is used to copy objects and merge them, like { ...base, headless: false }.

If the same key appears more than once, the last one wins. This is useful for building test configs, where a base config is reused and only a few values are changed.

Q13. What is the difference between a shallow copy and a deep copy?

A shallow copy copies only the top level. Spread { ...obj } makes a shallow copy. Nested objects inside are still shared, so changing them changes the original too.

A deep copy copies every level, so nothing is shared. In Node.js, structuredClone(obj) makes a deep copy. Deep copies are useful when test data must not affect other tests.

Q14. What is the rest operator?

The rest operator also uses ..., but it collects the leftover items. In destructuring, const { password, ...safeUser } = user puts all keys except password into safeUser.

In a function, function total(...nums) collects all arguments into an array. The rest part must always be the last one.

Q15. What is the difference between spread and rest?

Both use the same ... syntax, but they do opposite jobs. Spread expands, or opens up, an object or array into separate items.

Rest collects many items into one object or array. A simple rule: on the right side of = or in a function call, it is spread. On the left side of = or in function parameters, it is rest.

Q16. What is the output of this object reference code?

const a = { count: 1 };
const b = a;
b.count = 5;
console.log(a.count, a === b);
console.log({ x: 1 } === { x: 1 });

Output

5 true
false

const b = a does not copy the object. Both variables point to the same object in memory, so changing b.count also changes a.count, and a === b is true.

In the last line, two separate objects are created. They look the same, but they are different objects in memory, so the result is false.

Q17. What is the output of this spread copy code?

const orig = { name: "Amit", address: { city: "Pune" } };
const copy = { ...orig };
copy.name = "Riya";
copy.address.city = "Delhi";
console.log(orig);

Output

{ name: 'Amit', address: { city: 'Delhi' } }

Spread makes a shallow copy. The top-level name is copied as its own value, so changing copy.name does not affect orig.

But address is a nested object, and only its reference is copied. Both objects share the same address, so the city changes to "Delhi" in orig too.

Q18. What is the output of this merge code?

const merged = { a: 1, b: 2, ...{ b: 3, c: 4 }, a: 9 };
console.log(merged);

Output

{ a: 9, b: 3, c: 4 }

Keys are applied from left to right, and a later value overwrites an earlier one. The spread changes b to 3 and adds c, then the last a: 9 overwrites a.

The order of keys stays as they were first added: a, then b, then c. Only the values are updated.

Q19. What is the output of this dot vs bracket code?

const obj = { name: "Amit" };
const k = "name";
console.log(obj.k, obj[k]);

Output

undefined Amit

obj.k looks for a key literally named "k". There is no such key, so it returns undefined.

obj[k] uses the value of the variable k, which is "name". So it reads obj["name"] and returns Amit.

Q20. What is the output of this destructuring code?

const person = { name: "Amit", city: "Pune" };
const { name: fullName, age = 30, city } = person;
console.log(fullName, age, city);

Output

Amit 30 Pune

name: fullName reads the name key and stores it in a new variable called fullName. So fullName is Amit.

The object has no age key, so the default value 30 is used. city is read normally and gives Pune.

Chapter 8: Functions

1. Overview

A function is a reusable block of code that does one job. We write it once and call it many times with different inputs. In test automation, we use functions for login steps, data helpers, API calls and checks.

2. Core Concepts

2.1 Function Declaration

We create a function with the function keyword and a name. We call it by its name with brackets.

function greet(name) {
  return "Hello, " + name;
}
console.log(greet("Amit"));  // Hello, Amit

2.2 Function Expression

A function expression stores a function inside a variable. We call it using the variable name.

const isPass = function (score) {
  return score >= 40;
};
console.log(isPass(55));  // true

2.3 Arrow Function

An arrow function is a shorter way to write a function. With one expression and no curly braces, the value is returned automatically. To return an object directly, we wrap it in brackets.

const square = (n) => n * n;
const add = (a, b) => {
  return a + b;
};
console.log(square(4), add(2, 3));  // 16 5

const getUser = () => ({ name: "Amit" });
console.log(getUser());  // { name: 'Amit' }

2.4 Parameters

Parameters are the names in the function definition. Arguments are the values we pass. A missing argument becomes undefined. Extra arguments are ignored.

function login(username, password) {
  console.log(username, password);
}
login("amit");                      // amit undefined
login("amit", "secret", "extra");   // amit secret

2.5 Default Parameters

A default value is used when the argument is missing or undefined. It is not used for null.

function openBrowser(name = "chrome", headless = true) {
  return `${name} headless=${headless}`;
}
console.log(openBrowser());                  // chrome headless=true
console.log(openBrowser("firefox", false));  // firefox headless=false
console.log(openBrowser(undefined, false));  // chrome headless=false
console.log(openBrowser(null));              // null headless=true

2.6 return

return sends a value back and stops the function. A function without return gives undefined.

function getStatus(code) {
  if (code === 200) return "OK";
  return "Error";
}
console.log(getStatus(200), getStatus(500));  // OK Error

function logOnly() {
  console.log("Logging");
}
const result = logOnly();
console.log(result);

Output

OK Error
Logging
undefined

2.7 Hoisting

Function declarations are hoisted, so we can call them before they are written. Functions stored in const or let cannot be used before that line.

console.log(sum(2, 3));  // 5
function sum(a, b) {
  return a + b;
}

console.log(multiply(2, 3));
const multiply = (a, b) => a * b;

Output

5
ReferenceError: Cannot access 'multiply' before initialization

2.8 Scope

Scope decides where a variable can be used. Global variables work everywhere. Variables inside a function or a { } block work only inside it.

const env = "qa";
function showEnv() {
  const url = "https://qa.test.com";
  console.log(env, url);
}
showEnv();         // qa https://qa.test.com
console.log(url);

Output

qa https://qa.test.com
ReferenceError: url is not defined

An inner function can remember variables of its outer function, even after the outer function ends. This is called a closure.

function counter() {
  let count = 0;
  return () => {
    count++;
    return count;
  };
}
const next = counter();
console.log(next(), next(), next());  // 1 2 3

2.9 Callbacks

A callback is a function passed into another function, to be called later. Array methods like map also take callbacks.

function runTest(name, callback) {
  console.log("Running " + name);
  callback(name);
}
runTest("Login test", (n) => console.log(n + " finished"));

console.log([1, 2, 3].map((n) => n * 10));

Output

Running Login test
Login test finished
[ 10, 20, 30 ]

2.10 Methods in Objects

A function inside an object is called a method. Inside a normal method, this means the object. An arrow function does not get its own this, so it is not good for methods.

const user = {
  name: "Amit",
  greet() {
    return "Hi, " + this.name;
  },
  arrowGreet: () => "Hi, " + this.name,
};
console.log(user.greet());       // Hi, Amit
console.log(user.arrowGreet());  // Hi, undefined

2.11 async / await Basics

An async function always returns a Promise. Inside it, await pauses until a Promise finishes, so slow tasks read like normal step-by-step code.

function fetchUser() {
  return new Promise((resolve) =>
    setTimeout(() => resolve({ id: 1, name: "Amit" }), 1000)
  );
}

async function main() {
  console.log("Start");
  const user = await fetchUser();
  console.log(user);
  console.log("End");
}
main();

Output

Start
{ id: 1, name: 'Amit' }   (after 1 second)
End

3. Interview Questions and Answers

Q1. What is a function and why is it used?

A function is a named block of code that does one task. It can take inputs, called parameters, and can give back a result with return.

Functions remove repeated code and make scripts easy to read and maintain. In test automation, common steps like login, creating test data or checking a response are written once as functions and reused in many tests.

Q2. What is the difference between a function declaration and a function expression?

A function declaration starts with the function keyword and a name, like function greet() {}. It is hoisted, so it can be called before the line where it is written.

A function expression stores a function in a variable, like const greet = function () {}. It can only be called after that line runs. Calling it earlier gives a ReferenceError.

Q3. What is an arrow function and how is it different from a normal function?

An arrow function is a shorter way to write a function using =>. If the body is a single expression without curly braces, the value is returned automatically, like (n) => n * n.

The main difference is this. An arrow function does not have its own this, it takes it from the outside code. So arrow functions are great for callbacks, but not for object methods that need this.

Q4. What is the difference between parameters and arguments?

Parameters are the names written in the function definition, like username and password. Arguments are the real values passed when the function is called, like "amit".

JavaScript does not check the count. A missing argument becomes undefined, and extra arguments are simply ignored.

Q5. What are default parameters?

Default parameters give a value to a parameter when no argument is passed. For example, function openBrowser(name = "chrome") uses "chrome" when no name is given.

The default is used only when the argument is undefined or missing. If null is passed, the default is not used, and the value stays null.

Q6. What does return do, and what is returned if there is no return?

return sends a value back to the caller and stops the function right there. Any code after it inside the function does not run.

If a function has no return, or has an empty return, it gives back undefined.

Q7. What is hoisting?

Hoisting means JavaScript reads declarations before running the code. Function declarations are fully hoisted, so they can be called before they are written in the file.

Variables made with let and const are also known early, but they cannot be used before their line. This is why a function expression or arrow function stored in const gives ReferenceError: Cannot access 'multiply' before initialization when called too early.

Q8. What is scope? What types of scope are there?

Scope is the area of code where a variable can be used. Global scope means the variable is outside all functions and can be used everywhere.

Function scope means a variable made inside a function can only be used inside that function. Block scope means a let or const variable inside { }, like in an if or loop, can only be used inside that block. Using it outside gives a ReferenceError.

Q9. What is a closure?

A closure is when an inner function remembers the variables of its outer function, even after the outer function has finished running.

For example, a counter function can return an inner function that keeps increasing a private count variable. Closures are used to keep data private and to build helper functions that remember settings.

Q10. What is a callback function?

A callback is a function passed as an argument to another function, so that it can be called later. The other function decides when to run it.

Array methods like map, filter and forEach use callbacks. setTimeout also takes a callback that runs after a delay.

Q11. What is a method, and what does this mean inside it?

A method is a function stored inside an object. It is called with the object name, like user.greet().

Inside a normal method, this refers to the object that called it. So this.name reads the name key of that same object.

Q12. Why should arrow functions not be used as object methods?

Arrow functions do not have their own this. Inside an arrow method, this does not point to the object, so this.name gives undefined.

For methods that need to read the object's own data, the short method syntax greet() {} or a normal function is used.

Q13. What does an async function return?

An async function always returns a Promise. A Promise is an object that will hold a result in the future. Even if the function returns a simple value like 200, it is wrapped in a Promise.

So console.log(getStatus()) prints Promise { 200 }, not 200. To get the real value, await or .then() is used.

Q14. What does await do?

await pauses the async function until the Promise finishes, then gives back its result. It makes slow work, like API calls or file reading, look like simple step-by-step code.

await pauses only that one async function. The rest of the program keeps running. It can only be used inside an async function, or at the top level of an ES module.

Q15. How are errors handled in async/await code?

Errors in async code are handled with try and catch. The await call is placed inside try, and if the Promise fails, the code jumps to catch.

For example, if a login function throws new Error("Login failed"), the catch block can read e.message and print "Login failed". Without this, the error is unhandled and can crash the test.

Q16. What is the output of this hoisting code?

console.log(sum(2, 3));
function sum(a, b) {
  return a + b;
}

console.log(multiply(2, 3));
const multiply = (a, b) => a * b;

Output

5
ReferenceError: Cannot access 'multiply' before initialization

sum is a function declaration, so it is fully hoisted. It can be called before it is written, and it prints 5.

multiply is an arrow function stored in const. A const cannot be used before its line, so the call throws a ReferenceError.

Q17. What is the output of this default parameter code?

function openBrowser(name = "chrome", headless = true) {
  return `${name} headless=${headless}`;
}
console.log(openBrowser(undefined, false));
console.log(openBrowser(null));

Output

chrome headless=false
null headless=true

In the first call, undefined is passed for name, so the default "chrome" is used. headless gets false.

In the second call, null is a real value, so the default is not used and "null" is printed. headless is missing, so its default true is used.

Q18. What is the output when return is on its own line?

function getResult() {
  return
    "done";
}
console.log(getResult());

Output

undefined

JavaScript adds a semicolon right after return when the line ends there. This is called automatic semicolon insertion. So the function returns nothing.

The "done" line never runs. The value to return must start on the same line as return.

Q19. What is the output of this method and arrow function code?

const user = {
  name: "Amit",
  greet() {
    return "Hi, " + this.name;
  },
  arrowGreet: () => "Hi, " + this.name,
};
console.log(user.greet());
console.log(user.arrowGreet());

Output

Hi, Amit
Hi, undefined

greet is a normal method, so this is the user object, and this.name is Amit.

arrowGreet is an arrow function, so it does not get this from user. In a normal Node.js file, the outside this is an empty object, so this.name is undefined.

Q20. What is the output order of this async code?

async function order() {
  console.log("A");
  await null;
  console.log("B");
}
console.log("1");
order();
console.log("2");

Output

1
A
2
B

First "1" is printed. Then order() starts and runs normally until the first await, so "A" is printed right away.

At await, the function pauses and control goes back to the main code, which prints "2". After the main code finishes, the function continues and prints "B".

Chapter 9: Promises & async/await

1. Overview

A Promise is an object that will give us a result later, like an API response or file data. We use then/catch or async/await to wait for that result. In test automation, almost every browser and API action is asynchronous, so this is very important.

2. Core Concepts

2.1 Promise States

A Promise has three states: pending (still working), fulfilled (success with a value) and rejected (failed with an error). Once it is fulfilled or rejected, it never changes again.

const pending = new Promise(() => {});
console.log(pending);  // Promise { <pending> }

const done = Promise.resolve("Login OK");
console.log(done);     // Promise { 'Login OK' }

const later = new Promise((resolve) => setTimeout(() => resolve(200), 100));
console.log(later);    // Promise { <pending> }
setTimeout(() => console.log(later), 150);  // Promise { 200 }

2.2 Creating a Promise

We create a Promise with new Promise. Inside, we call resolve(value) for success and reject(error) for failure.

function getStatus(ok) {
  return new Promise((resolve, reject) => {
    if (ok) resolve(200);
    else reject(new Error("Server down"));
  });
}

2.3 then / catch / finally

then runs on success. catch runs on failure. finally runs in both cases, good for cleanup.

getStatus(true)
  .then((code) => console.log("Status:", code))
  .catch((err) => console.log("Error:", err.message));

getStatus(false)
  .then((code) => console.log("Status:", code))
  .catch((err) => console.log("Error:", err.message))
  .finally(() => console.log("Done"));

Output

Status: 200
Error: Server down
Done

2.4 Promise Chaining

Each then returns a new Promise. The value we return goes to the next then.

Promise.resolve(2)
  .then((n) => n * 10)
  .then((n) => n + 5)
  .then((n) => console.log(n));  // 25

2.5 Promise.all

Promise.all runs many Promises together and waits for all of them. It gives an array of results in the same order. If any one fails, the whole thing fails.

const wait = (ms) => new Promise((r) => setTimeout(r, ms));
const getUser = () => wait(300).then(() => ({ name: "Amit" }));
const getCourses = () => wait(200).then(() => ["JS", "TS"]);

async function main() {
  const [user, courses] = await Promise.all([getUser(), getCourses()]);
  console.log(user, courses);  // (after 300 ms)

  try {
    await Promise.all([
      Promise.resolve(1),
      Promise.reject(new Error("API 2 failed")),
    ]);
  } catch (e) {
    console.log("Caught:", e.message);
  }
}
main();

Output

{ name: 'Amit' } [ 'JS', 'TS' ]   (after 300 ms)
Caught: API 2 failed

2.6 setTimeout

setTimeout runs a function once after a delay in milliseconds. The rest of the code does not wait for it.

console.log("Start");
setTimeout(() => console.log("Timer done"), 1000);
console.log("End");

Output

Start
End
Timer done   (after 1 second)

2.7 Error Handling with async/await

With async/await, we use try/catch/finally. If an awaited Promise rejects, the code jumps to catch.

async function login(password) {
  if (password !== "secret") throw new Error("Invalid password");
  return "Welcome";
}

async function runTest() {
  try {
    console.log(await login("secret"));
    console.log(await login("wrong"));
  } catch (err) {
    console.log("Test failed:", err.message);
  } finally {
    console.log("Cleanup");
  }
}
runTest();

Output

Welcome
Test failed: Invalid password
Cleanup

3. Interview Questions and Answers

Q1. What is a Promise?

A Promise is an object that stands for a result that will come in the future. It is used for slow work like API calls, file reading or browser actions, where the answer is not ready right away.

Instead of blocking the program, the Promise is returned at once. Later it gives either a value on success or an error on failure, and the code reacts using then/catch or await.

Q2. What are the states of a Promise?

A Promise has three states. Pending means the work is still going on. Fulfilled means it finished with a value. Rejected means it failed with an error.

Fulfilled and rejected are together called settled. Once settled, a Promise never changes. If resolve is called twice, only the first call counts, and later resolve or reject calls are ignored.

Q3. How is a Promise created?

A Promise is created with new Promise((resolve, reject) => { ... }). The function inside is called the executor, and it runs immediately.

Inside the executor, resolve(value) is called on success and reject(error) on failure. For quick ready-made Promises, Promise.resolve(value) and Promise.reject(error) can be used.

Q4. What is the use of then, catch and finally?

then runs when the Promise is fulfilled and receives the value. catch runs when the Promise is rejected and receives the error.

finally runs in both cases and gets no value. It is used for cleanup work, like closing a browser or a database connection, after a test step.

Q5. What is Promise chaining?

Promise chaining means writing many then calls one after another. Each then returns a new Promise, and the value returned from one then is passed to the next.

One catch at the end can handle an error from any step in the chain. After a catch returns a value, the chain continues normally with the next then.

Q6. Why are Promises better than plain callbacks?

With plain callbacks, each async step goes inside the previous callback. Many steps create deep nested code that is hard to read, often called "callback hell".

Promises keep the code flat with chaining, and errors are handled in one place with catch. async/await, which is built on Promises, makes it even cleaner.

Q7. What is the difference between then/catch and async/await?

Both work with Promises and do the same job. then/catch uses chained callback functions.

async/await lets async code look like normal step-by-step code. It is easier to read, easier to debug, and errors are handled with normal try/catch. Most modern test code uses async/await.

Q8. What is Promise.all and when is it used?

Promise.all takes an array of Promises and runs them at the same time. It returns one Promise that gives an array of all results, in the same order as the input, not in the order they finished.

It is used when tasks do not depend on each other, like creating three test users or calling several APIs together. This saves time compared to waiting for each one.

Q9. What happens if one Promise in Promise.all fails?

Promise.all fails fast. As soon as any one Promise rejects, the whole Promise.all rejects with that error.

The results of the successful Promises are not returned. So Promise.all should be wrapped in try/catch when used with await.

Q10. What is the difference between running awaits one by one and using Promise.all?

Writing await on each call one by one runs them in sequence. If two tasks take 1 second each, the total is about 2 seconds.

Starting both and using await Promise.all([...]) runs them in parallel, so the total is about 1 second. Sequence is used when one step needs the result of another, like login before getting the profile.

Q11. What is setTimeout?

setTimeout runs a function once after a given delay in milliseconds, like setTimeout(fn, 1000) for 1 second. It does not block the program, so the next lines run immediately.

The delay is the minimum wait, not an exact time. In tests, it is often wrapped in a Promise to make a simple wait helper, like const wait = (ms) => new Promise((r) => setTimeout(r, ms)).

Q12. Does setTimeout with 0 delay run immediately?

No. setTimeout(fn, 0) still waits until all the current normal code has finished. Only then is the function run.

Promise callbacks like then run before timers. JavaScript keeps Promise callbacks in a higher priority queue, called the microtask queue, and timers in a normal queue. So a resolved then runs before a setTimeout of 0.

Q13. How are errors handled with async/await?

The await calls are put inside a try block. If any awaited Promise rejects or a throw happens, the code jumps to catch, which receives the error object.

A finally block can be added for cleanup, and it always runs. This keeps a failing test step from crashing the whole run and gives a clear error message.

Q14. What happens if await is forgotten?

Without await, the variable holds the Promise itself, not the result. For example, logging it prints something like Promise { 'abc123' } instead of abc123.

The code also does not wait, so the next steps may run too early. In tests, this causes flaky failures, so every async call must be awaited.

Q15. What is an unhandled Promise rejection?

An unhandled rejection happens when a Promise fails and there is no catch or try/catch to handle it.

In Node.js, an unhandled rejection stops the program with an error. To avoid it, every Promise should be awaited inside try/catch or have a catch at the end of its chain.

Chapter 10: Error Handling

1. Overview

Error handling means catching problems while the code runs, so the program does not crash. We use try/catch/finally to handle errors and throw to raise our own errors. In test automation, this helps us log clear failure messages and always run cleanup steps.

2. Core Concepts

2.1 try / catch

We put risky code inside try. If an error happens, the code jumps to catch, and the program keeps running.

try {
  const user = null;
  console.log(user.name);
} catch (error) {
  console.log("Caught:", error.message);
}
console.log("Test continues");

Output

Caught: Cannot read properties of null (reading 'name')
Test continues

2.2 finally

finally always runs, with or without an error. We use it for cleanup, like closing a browser.

function runStep(fail) {
  try {
    console.log("Opening browser");
    if (fail) throw new Error("Page not found");
    console.log("Step passed");
  } catch (err) {
    console.log("Step failed:", err.message);
  } finally {
    console.log("Closing browser");
  }
}
runStep(false);
runStep(true);

Output

Opening browser
Step passed
Closing browser
Opening browser
Step failed: Page not found
Closing browser

2.3 throw

throw creates our own error and stops the current code. We use it when a check fails.

function checkStatus(code) {
  if (code !== 200) {
    throw new Error(`Expected 200 but got ${code}`);
  }
  return "OK";
}

try {
  console.log(checkStatus(200));
  console.log(checkStatus(404));
} catch (e) {
  console.log(e.message);
}

Output

OK
Expected 200 but got 404

2.4 Error Object

We create an error with new Error("message"). It has name, message and stack. The stack shows where the error happened.

const err = new Error("Login failed");
console.log(err.name);               // Error
console.log(err.message);            // Login failed
console.log(err instanceof Error);   // true
console.log(typeof err.stack);       // string
console.log(String(err));            // Error: Login failed

2.5 Common Built-in Error Types

JavaScript has built-in error types. Each has its own name.

try { console.log(total); }
catch (e) { console.log(e.name + ": " + e.message); }

try { null.toUpperCase(); }
catch (e) { console.log(e.name + ": " + e.message); }

try { const login = undefined; login(); }
catch (e) { console.log(e.name + ": " + e.message); }

try { new Array(-1); }
catch (e) { console.log(e.name + ": " + e.message); }

Output

ReferenceError: total is not defined
TypeError: Cannot read properties of null (reading 'toUpperCase')
TypeError: login is not a function
RangeError: Invalid array length

2.6 Checking the Error Type

We can throw built-in types like TypeError too. Inside catch, instanceof tells us which type it is.

try {
  throw new TypeError("Age must be a number");
} catch (e) {
  if (e instanceof TypeError) {
    console.log("Type problem:", e.message);
  }
}
// Type problem: Age must be a number

3. Interview Questions and Answers

Q1. What is error handling and why is it important?

Error handling is the way a program deals with problems that happen while it runs, like a missing value, a failed API call or bad data. Without it, one error can stop the whole program.

In test automation, it helps show clear failure messages, take screenshots or logs on failure, and always run cleanup steps like closing the browser or deleting test data.

Q2. How does try/catch work?

Code that may fail is put inside try. If an error happens, the rest of the try block is skipped and the code jumps to catch.

The catch block receives the error object, usually named error or e. If no error happens, catch is skipped. After that, the program continues normally.

Q3. What is the finally block?

finally is an optional block after try or catch. It always runs, whether an error happened or not, and even if there is a return inside try or catch.

It is used for cleanup work, like closing the browser, closing a database connection or logging the end of a test.

Q4. Can try be used without catch?

Yes. try can be used with only finally. In that case, the error is not handled there. The finally block runs, and then the error goes up to the outer code.

But try alone, without catch or finally, is a syntax error. At least one of them is required.

Q5. What does throw do?

throw raises an error on purpose. The current code stops at once, and control goes to the nearest catch block.

It is used when a check fails, like throw new Error("Expected 200 but got 404"). If there is no catch anywhere, the program stops and prints the error.

Q6. What properties does an Error object have?

The main properties are name, message and stack. name is the error type, like "Error" or "TypeError". message is the text passed when the error was created.

stack is a string that shows the line and function where the error happened. It is very helpful for debugging failed tests.

Q7. Why should new Error() be thrown instead of a plain string?

JavaScript allows throwing anything, like throw "Timeout". But a string has no message, name or stack, so e.message becomes undefined.

An Error object gives a clear message and a stack trace showing where it happened. Test runners also show Error objects much better in reports.

Q8. What are the common built-in error types?

ReferenceError happens when a variable does not exist. TypeError happens when a value is used in a wrong way, like reading a property of null or calling something that is not a function.

SyntaxError happens when the code or data is written wrongly, like bad JSON in JSON.parse. RangeError happens when a number is outside the allowed range, like new Array(-1).

Q9. What is the difference between ReferenceError and TypeError?

ReferenceError means the name itself is unknown. For example, using total when it was never declared gives ReferenceError: total is not defined.

TypeError means the variable exists, but its value is the wrong kind for the action. For example, calling login() when login is undefined gives TypeError: login is not a function.

Q10. How can different error types be handled differently?

Inside catch, the instanceof operator checks the type of the error, like e instanceof TypeError. Each type can then get its own message or action.

Another way is to check e.name, like e.name === "TypeError". Errors that are not expected can be thrown again so they are not hidden.

Q11. What does re-throwing an error mean?

Re-throwing means catching an error, doing something with it, and then throwing it again with throw e. The outer code then receives the same error.

It is useful when a helper needs to log the error or take a screenshot, but the test must still fail. Silently catching every error would hide real bugs.

Q12. Can catch be written without the error parameter?

Yes. Modern JavaScript allows catch { ... } without (e). This is called optional catch binding.

It is used when the error details are not needed, like printing "Invalid data" when JSON.parse fails. If the message is needed, the parameter must be written.

Q13. Does try/catch catch errors inside setTimeout?

No. A normal try/catch only catches errors that happen while its own code is running. A setTimeout callback runs later, after the try block has already finished.

To catch such errors, the try/catch must be placed inside the callback itself. With Promises, await inside try/catch or a .catch() is used.

Q14. Is it a good practice to catch every error and do nothing?

No. An empty catch block hides errors. The test may pass even when something is broken, which gives false results.

A good catch should log a clear message, add useful details, or re-throw the error. Errors should be caught only where something useful can be done with them.

Q15. How does error handling help in test automation?

Custom checks with throw new Error(...) give clear failure messages, like "Expected 200 but got 404". This makes debugging much faster.

finally makes sure cleanup always happens, like closing the browser or logging out. try/catch around retries also lets a step be tried again before failing.

Q16. What is the output order of this try/catch/finally code?

  try {
    console.log("A");
    throw new Error("B");
    console.log("C");
  } catch (e) {
    console.log(e.message);
    return "D";
  } finally {
    console.log("E");
  }
}
console.log(test());

Output

A
B
E
D

"A" is printed, then the error is thrown, so "C" never runs. catch prints the message "B" and prepares to return "D".

Before the function really returns, finally runs and prints "E". Only then does console.log outside print the returned value "D".

Q17. What is the output when both try and finally have return?

  try {
    return "try";
  } finally {
    return "finally";
  }
}
console.log(getResult());

Output

finally

The try block wants to return "try", but finally always runs before the function ends.

A return inside finally replaces the earlier return value. So the function returns "finally". This is why return inside finally should be avoided.

Q18. What is the output of this code with return in try?

  try {
    return "try";
  } finally {
    console.log("finally runs");
  }
}

The return in try does not skip finally. The value "try" is kept aside, and finally runs first and prints "finally runs".

Since finally has no return, the saved value "try" is returned and printed.

Q19. What is the output when a string is thrown?

  throw "Timeout";
} catch (e) {
  console.log(e, typeof e, e.message);
}

Output

Timeout string undefined

The thrown value is a plain string, not an Error object. So e is just "Timeout", and its type is "string".

A string has no message property, so e.message is undefined. This is why new Error("Timeout") is the better choice.

Q20. What is the output of this nested try/catch with re-throw?

    throw new Error("DB down");
  } catch (e) {

The inner catch handles the error first and prints "Inner: DB down". Then it throws the same error again.

Before the error leaves the inner block, the inner finally runs. After that, the outer catch receives the same error and prints "Outer: DB down".

Chapter 11: Classes & OOP

1. Overview

A class is a blueprint for creating objects that share the same data and methods. OOP (Object-Oriented Programming) means building code around such objects. In test automation, we use classes for Page Objects, API clients and test data builders.

2. Core Concepts

2.1 Class and Object

A class is the blueprint. An object is a real thing made from it with the new keyword. One class can make many objects.

class Course {
  constructor(title) {
    this.title = title;
  }
}
const js = new Course("JS");
const ts = new Course("TS");
console.log(js);                    // Course { title: 'JS' }
console.log(ts.title);              // TS
console.log(js instanceof Course);  // true

2.2 Constructor

The constructor runs automatically when we use new. It sets the starting data of the object. A class cannot be called without new.

class User {
  constructor(name, role) {
    this.name = name;
    this.role = role;
  }
}
const u1 = new User("Amit", "tester");
console.log(u1);  // User { name: 'Amit', role: 'tester' }

User("Riya", "admin");

Output

User { name: 'Amit', role: 'tester' }
TypeError: Class constructor User cannot be invoked without 'new'

2.3 this

Inside a class, this means the current object. Each object keeps its own values. Returning this lets us chain method calls.

class Counter {
  constructor() {
    this.count = 0;
  }
  add() {
    this.count++;
    return this;
  }
}
const c = new Counter();
c.add().add();
console.log(c.count);  // 2

2.4 Methods

Methods are functions written inside the class. All objects share them and call them with a dot.

class User {
  constructor(name) {
    this.name = name;
  }
  greet() {
    return `Hi, I am ${this.name}`;
  }
}
const u = new User("Amit");
console.log(u.greet());  // Hi, I am Amit

2.5 Class Fields

Class fields set default values directly in the class body, without a constructor.

class Browser {
  name = "chrome";
  headless = true;
  timeout = 30000;
}
const b = new Browser();
console.log(b);  // Browser { name: 'chrome', headless: true, timeout: 30000 }
b.name = "firefox";
console.log(b.name);  // firefox

2.6 static

Static fields and methods belong to the class itself, not to objects. We call them with the class name.

class Helper {
  static baseUrl = "https://qa.test.com";
  static square(n) {
    return n * n;
  }
}
console.log(Helper.square(4));  // 16
console.log(Helper.baseUrl);    // https://qa.test.com

const h = new Helper();
console.log(h.baseUrl);         // undefined
h.square(4);

Output

16
https://qa.test.com
undefined
TypeError: h.square is not a function

2.7 extends and super

extends makes a child class that gets everything from the parent. super() calls the parent constructor and must come before using this.

class Person {
  constructor(name) {
    this.name = name;
  }
  intro() {
    return `I am ${this.name}`;
  }
}
class Student extends Person {
  constructor(name, course) {
    super(name);
    this.course = course;
  }
  study() {
    return `${this.name} studies ${this.course}`;
  }
}
const s = new Student("Riya", "JS");
console.log(s.intro());  // I am Riya
console.log(s.study());  // Riya studies JS
console.log(s);          // Student { name: 'Riya', course: 'JS' }

2.8 Method Overriding

A child class can write a method with the same name as the parent. The child version is used. super.method() still calls the parent version.

class BasePage {
  open() {
    return "Opening base page";
  }
}
class LoginPage extends BasePage {
  open() {
    return "Opening login page";
  }
  openBoth() {
    return super.open() + " + " + this.open();
  }
}
const lp = new LoginPage();
console.log(lp.open());      // Opening login page
console.log(lp.openBoth());  // Opening base page + Opening login page

2.9 Async Methods

A class method can be async. It returns a Promise, so we use await when calling it.

class ApiClient {
  constructor(baseUrl) {
    this.baseUrl = baseUrl;
  }
  async getUser(id) {
    await new Promise((r) => setTimeout(r, 1000));
    return { id, name: "Amit", url: `${this.baseUrl}/users/${id}` };
  }
}

async function main() {
  const api = new ApiClient("https://qa.test.com");
  const user = await api.getUser(7);
  console.log(user);
}
main();

Output

{ id: 7, name: 'Amit', url: 'https://qa.test.com/users/7' }   (after 1 second)

2.10 Getters and Setters

A getter (get) is read like a property, without brackets. A setter (set) runs when we assign a value, so we can check it first.

class Account {
  constructor(first, last) {
    this.first = first;
    this.last = last;
    this._age = 0;
  }
  get fullName() {
    return `${this.first} ${this.last}`;
  }
  get age() {
    return this._age;
  }
  set age(value) {
    if (value < 0) {
      console.log("Invalid age");
      return;
    }
    this._age = value;
  }
}
const a = new Account("Amit", "Sharma");
console.log(a.fullName);  // Amit Sharma
a.age = 25;
console.log(a.age);       // 25
a.age = -5;               // Invalid age
console.log(a.age);       // 25

2.11 Private Fields (#)

A field starting with # is private. Only code inside the class can use it. Outside code cannot read or change it directly.

class BankAccount {
  #balance = 0;
  deposit(amount) {
    this.#balance += amount;
  }
  getBalance() {
    return this.#balance;
  }
}
const acc = new BankAccount();
acc.deposit(500);
console.log(acc.getBalance());  // 500
console.log(acc.balance);       // undefined
console.log(Object.keys(acc));  // []

Using acc.#balance outside the class does not even run:

Output

SyntaxError: Private field '#balance' must be declared in an enclosing class

3. Interview Questions and Answers

Q1. What is a class and what is an object?

A class is a blueprint or template. It describes what data and methods its objects will have. An object is a real instance made from that class using new.

For example, a User class can create many user objects, each with its own name and role, but all sharing the same methods. In testing, a LoginPage class is the blueprint, and new LoginPage() is the object used in the test.

Q2. What are the main principles of OOP?

The four main principles are encapsulation, inheritance, polymorphism and abstraction. Encapsulation means keeping data and methods together and hiding inner details, like with private fields.

Inheritance means a child class reuses a parent class with extends. Polymorphism means the same method name can act differently in different classes, like overriding. Abstraction means showing only simple methods, like login(), and hiding the complex steps inside.

Q3. What is a constructor?

A constructor is a special method named constructor. It runs automatically when an object is created with new, and it sets the starting values using this.

A class can have only one constructor. If none is written, an empty one is used. Calling a class without new gives TypeError: Class constructor User cannot be invoked without 'new'.

Q4. What does this mean inside a class?

this refers to the current object, the one that is calling the method or being created. So this.name means the name of that specific object.

Each object has its own values, so this gives different data for different objects. If a method returns this, calls can be chained, like c.add().add().

Q5. What are class fields?

Class fields are properties written directly in the class body, like timeout = 30000. Every new object gets them with these starting values.

They make the code shorter when values do not come from constructor arguments. Fields are set first, and then the constructor body runs.

Q6. What is a static method or field?

A static method or field belongs to the class itself, not to its objects. It is called using the class name, like Helper.square(4), and no object is needed.

Objects cannot use it, so h.square(4) gives TypeError: h.square is not a function. Static members are used for helpers, shared config like a base URL, and counters.

Q7. What is inheritance and how is it done?

Inheritance means a child class gets all fields and methods of a parent class. It is done with extends, like class Student extends Person.

It avoids repeated code. In test automation, a BasePage can hold common methods like opening a URL, and every page class can extend it.

Q8. What is super and why is it needed?

super() calls the parent class constructor. In a child constructor, it must be called before using this. Otherwise, the code throws a ReferenceError saying the super constructor must be called first.

super.method() calls the parent version of a method. This is useful when a child overrides a method but still wants to run the parent logic too.

Q9. What is method overriding?

Overriding means a child class writes a method with the same name as the parent method. When the method is called on a child object, the child version runs.

It lets each class give its own behavior. For example, every page class can have its own open() method that opens its own URL.

Q10. Can a class method be async?

Yes. Writing async before a method name makes it async. It always returns a Promise, so the caller uses await, like await api.getUser(7).

This is very common in test automation, because Page Object and API client methods usually do slow work like clicking, waiting or sending requests. The constructor itself cannot be async.

Q11. What are getters and setters?

A getter is a method with get that is read like a normal property, without brackets, like a.fullName. It is used to build a value from other data.

A setter is a method with set that runs when a value is assigned, like a.age = 25. It is used to check the value before saving it, for example, refusing a negative age.

Q12. What are private fields?

Private fields start with #, like #balance. They can only be used inside the class. Outside code cannot read or change them, and they do not appear in Object.keys().

Using one outside the class, like acc.#balance, is a SyntaxError. Private fields protect data, so it can only change through safe methods like deposit(). This is encapsulation.

Q13. What is the difference between a private field (#) and a field starting with an underscore (_)?

A field like _age is only a naming habit. It tells other developers "do not touch this", but it is still fully public and can be read and changed from outside.

A field like #age is truly private. JavaScript itself blocks access from outside the class.

Q14. What is the instanceof operator?

instanceof checks if an object was made from a certain class or its parent classes. It returns true or false.

For a Student object that extends Person, both s instanceof Student and s instanceof Person are true. It is also used in catch blocks to check error types.

Q15. What is the Page Object Model and how do classes help?

The Page Object Model is a test design pattern where each web page has its own class. The class keeps the page's locators and actions, like login(username, password).

Tests call these simple methods instead of repeating low-level steps. If the page changes, only one class is updated. Inheritance from a BasePage class shares common actions across pages.

}

new User();

count is static, so there is only one copy, shared on the class itself. It does not belong to each object.

Each new User() runs the constructor, which adds 1 to User.count. After three objects, the value is 3.

Output

child

super() runs the parent constructor first, which sets type to "parent". Then the child constructor changes it to "child".

who() comes from the parent, but this is the child object. So it reads the current value, "child".

Chapter 12: Modules

1. Overview

A module is simply a JavaScript file that shares some of its code with other files. We export code from one file and import it in another. This keeps test projects clean, with page objects, helpers and test data in separate files.

2. Core Concepts

2.1 Two Module Systems

Node.js has two module systems. ES Modules (ESM) use import / export. CommonJS (CJS) uses require / module.exports. To use ESM in .js files, we add "type": "module" to package.json.

// package.json (for ES Modules)
{
  "type": "module"
}

2.2 Named Export and Import

A file can have many named exports. We import them with curly braces, using the exact same names.

// mathUtils.js
export const PI = 3.14;

export function add(a, b) {
  return a + b;
}

export const multiply = (a, b) => a * b;
// main.js
import { add, PI } from "./mathUtils.js";

console.log(add(2, 3), PI);  // 5 3.14

2.3 Renaming and Importing Everything

as gives an import a new name. import * as puts all named exports into one object.

import { multiply as times } from "./mathUtils.js";
import * as math from "./mathUtils.js";

console.log(times(4, 5));     // 20
console.log(math.add(1, 1));  // 2
console.log(math);

Output

20
2
[Module: null prototype] {
  PI: 3.14,
  add: [Function: add],
  multiply: [Function: multiply]
}

2.4 Default Export and Import

A file can have only one default export. We import it without curly braces and can give it any name. One file can have both default and named exports.

// LoginPage.js
export default class LoginPage {
  login(user) {
    return `Logging in as ${user}`;
  }
}
export const url = "/login";
// main.js
import LoginPage, { url } from "./LoginPage.js";
import Page from "./LoginPage.js";

const page = new LoginPage();
console.log(page.login("amit"), url);  // Logging in as amit /login
console.log(Page === LoginPage);       // true

2.5 Import Errors in ES Modules

Importing a name that is not exported fails before the code runs. Also, require does not exist inside an ES module.

import { sub } from "./mathUtils.js";

Output

SyntaxError: The requested module './mathUtils.js' does not provide an export named 'sub'
const math = require("./mathUtils.js");  // inside an ES module

Output

ReferenceError: require is not defined in ES module scope, you can use import instead

2.6 module.exports and require (CommonJS)

In CommonJS, we put what we share into module.exports. require returns that value. The .js part can be left out.

// config.js
module.exports = {
  baseUrl: "https://qa.test.com",
  timeout: 5000,
};
// main.js
const config = require("./config");
const { timeout } = require("./config");

console.log(config.baseUrl);  // https://qa.test.com
console.log(timeout);         // 5000

2.7 exports Shortcut and Exporting One Function

exports.name = value adds items one by one. To export just one function, we assign it directly to module.exports.

// helpers.js
exports.getEmail = () => "user1@test.com";
exports.TIMEOUT = 5000;

// logger.js
module.exports = function log(msg) {
  console.log(`[LOG] ${msg}`);
};
// main.js
const { getEmail, TIMEOUT } = require("./helpers");
const log = require("./logger");

console.log(getEmail(), TIMEOUT);  // user1@test.com 5000
log("Test started");               // [LOG] Test started

2.8 Built-in Modules

Node.js has built-in modules like path and fs. We load them by name, without ./.

const path = require("path");
// or in ESM: import path from "path";

console.log(path.basename("/tests/login.spec.js"));  // login.spec.js

3. Interview Questions and Answers

Q1. What is a module and why is it used?

A module is a separate JavaScript file that shares selected code, like functions, classes or values, with other files. Code inside a module is private unless it is exported.

Modules keep code organized, reusable and easy to maintain. In a test project, page objects, API helpers, test data and config are kept in their own modules and imported into test files.

Q2. What is the difference between ES Modules and CommonJS?

ES Modules are the modern JavaScript standard. They use import and export, and they work in both browsers and Node.js.

CommonJS is the older Node.js system. It uses require and module.exports. require runs while the code is running, but import is checked before the code runs, so a missing export is caught early.

Q3. How does Node.js decide if a file is an ES module or CommonJS?

By default, a .js file is treated as CommonJS. If the nearest package.json has "type": "module", .js files are treated as ES modules.

The file extension can also decide it. A .mjs file is always an ES module, and a .cjs file is always CommonJS.

Q4. What is the difference between a named export and a default export?

A file can have many named exports. They are imported with curly braces and must use the same name, like import { add } from "./mathUtils.js".

A file can have only one default export. It is imported without curly braces and can get any name, like import Page from "./LoginPage.js". A file can have both types together.

Q5. Which is better, named or default exports?

Named exports are often preferred in bigger projects. The names must match, so typing mistakes are caught early, and code editors can find and auto-import them easily.

Default exports are useful when a file has one main thing, like one page object class per file. Many teams use a default export for the main class and named exports for small helpers.

Q6. How can an import be renamed?

A named import is renamed with as, like import { multiply as times } from "./mathUtils.js". This avoids name clashes when two files export the same name.

A default import does not need as, because any name can be given directly. In CommonJS, renaming is done during destructuring, like const { add: sum } = require("./math").

Q7. What does import * as do?

import * as math from "./mathUtils.js" loads all named exports of a file into one object called a namespace. Each export is used with a dot, like math.add(1, 1).

It is useful when a file has many helpers and they should be grouped under one name. The namespace object is read-only, so its values cannot be changed from outside.

Q8. What is module.exports?

module.exports is the object that a CommonJS file shares. Whatever is assigned to it is what require returns in another file.

It can be an object with many items, or a single function or class, like module.exports = function log() {}. At the start, it is an empty object {}.

Q9. What is the difference between exports and module.exports?

exports is just a short name that points to the same object as module.exports. Adding keys like exports.TIMEOUT = 5000 works fine.

But writing exports = { ... } only changes the local short name, not module.exports. So require still returns the empty object. To export a new object or a single function, module.exports must be used.

Q10. Can import and require be mixed in the same file?

Inside an ES module, require is not available, and using it gives ReferenceError: require is not defined in ES module scope, you can use import instead.

Inside a CommonJS file, the import statement is not allowed. The usual rule is to pick one system for the whole project and use it everywhere.

Q11. What happens when a module is imported in many files?

A module runs only once, the first time it is loaded. Node.js saves the result in a cache. Every later require or import gets the same saved object.

This means shared state, like a counter or a config object, is the same for all files. It is useful for shared settings, but test data should not be changed in shared modules by mistake.

Q12. When is the file path needed in require or import?

For own files, a relative path is needed, like ./helpers or ../pages/LoginPage.js. Without ./, Node.js looks for a built-in module or an installed package instead.

In CommonJS, the .js extension can be left out. In ES modules, the full file name with .js must be written. Built-in modules like path and fs are loaded by name only.

Q13. What error appears if a required file does not exist?

In CommonJS, require throws an error with the code MODULE_NOT_FOUND, and the message says it cannot find the module.

In ES modules, importing a missing named export gives a SyntaxError, like "does not provide an export named 'sub'". Both errors usually mean a wrong path, a wrong name or a missing export.

Q14. How are modules used in a test automation framework?

Each page object class is kept in its own file and exported. Test files import only the pages they need. Helpers like random data generators, API clients and constants are also kept in separate modules.

Config values, like base URL and timeouts, are kept in one module and imported everywhere. When something changes, only one file is updated.

Q15. What does it mean that ES module imports are read-only?

An imported variable cannot be given a new value in the importing file. For example, writing count = 10 after importing count gives TypeError: Assignment to constant variable.

The value can only be changed by the module that exports it, usually through an exported function. This protects shared data from being changed by mistake.

Q16. What is the output when the same module is required twice?

// config.js
console.log("Loading config");
module.exports = { baseUrl: "https://qa.test.com" };

// main.js
const config = require("./config");
const again = require("./config.js");
console.log(config === again);

Output

Loading config
true

The first require runs config.js, so "Loading config" is printed. The result is saved in the module cache.

The second require points to the same file, so it does not run the file again. It returns the same cached object, so config === again is true.

Q17. What is the output when exports is reassigned?

// user.js
exports = { name: "Amit" };

// main.js
const user = require("./user");
console.log(user);

Output

{}

exports is only a local short name for module.exports. Assigning a new object to it breaks that link, and module.exports stays as the empty object.

require always returns module.exports, so {} is printed. The fix is module.exports = { name: "Amit" }.

Q18. What is the output of this CommonJS counter code?

// config.js
let retries = 0;
function addRetry() {
  retries++;
}
module.exports = {
  retries,
  addRetry,
  getRetries: () => retries,
};

// main.js
const config = require("./config");
config.addRetry();
config.addRetry();
console.log(config.retries, config.getRetries());

Output

0 2

When module.exports is built, retries is copied into the object as the number 0. Later changes to the local variable do not update that copy, so config.retries stays 0.

getRetries() reads the real local variable every time it is called. After two calls to addRetry(), it returns 2.

Q19. What is the output of this ES module counter code?

// counter.js
export let count = 0;
export function increment() {
  count++;
}

// main.js
import { count, increment } from "./counter.js";
console.log(count);
increment();
increment();
console.log(count);

Output

0
2

ES module imports are live bindings. This means the imported name is a live link to the variable inside the module, not a copy.

So after increment() runs twice inside counter.js, the importing file sees the new value 2. This is different from CommonJS, where a copied value does not update.

Chapter 13: JSON

1. Overview

JSON (JavaScript Object Notation) is a text format for storing and sending data. APIs send their request and response bodies as JSON. We also keep test data, like users and URLs, in .json files. In JavaScript, we use JSON.stringify() to turn data into JSON text and JSON.parse() to turn JSON text back into data.

2. Core Concepts

2.1 What JSON Looks Like

JSON looks like a JS object, but its rules are stricter. Keys must use double quotes. Strings must use double quotes. Trailing commas and comments are not allowed.

{
  "name": "Amit",
  "age": 25,
  "isActive": true,
  "courses": ["JS", "TS"],
  "address": { "city": "Pune" },
  "manager": null
}

2.2 JSON Data Types

JSON allows only 6 types: string, number, boolean, null, object and array. Values like undefined, functions, Date and NaN do not exist in JSON.

{
  "course": "JavaScript",
  "students": 40,
  "isOpen": false,
  "teacher": null,
  "tags": ["qa", "automation"],
  "room": { "floor": 2 }
}

2.3 JSON.stringify() - Object to JSON Text

JSON.stringify() turns a JS value into a JSON string. We use it to send data in an API body or to save it in a file.

const user = { name: "Amit", age: 25, isActive: true };
const text = JSON.stringify(user);

console.log(text);        // {"name":"Amit","age":25,"isActive":true}
console.log(typeof text); // string

2.4 Pretty Print with JSON.stringify()

The third argument adds spaces for indentation. The second argument is null when we do not need it. This is useful for readable logs.

const user = { name: "Amit", age: 25, isActive: true };
console.log(JSON.stringify(user, null, 2));

Output

{
  "name": "Amit",
  "age": 25,
  "isActive": true
}

2.5 Picking Only Some Keys

If the second argument is an array of key names, only those keys are kept. This helps us hide data like passwords in logs.

const user = { name: "Amit", age: 25, password: "Amit@123" };
console.log(JSON.stringify(user, ["name", "age"])); // {"name":"Amit","age":25}

2.6 What JSON.stringify() Skips

Keys with undefined or function values are removed from objects. Inside arrays, they become null. null stays as it is.

const user = { name: "Amit", city: undefined, greet() { return "hi"; }, score: null };
console.log(JSON.stringify(user));                   // {"name":"Amit","score":null}
console.log(JSON.stringify([1, undefined, () => 1])); // [1,null,null]

2.7 JSON.parse() - JSON Text to Object

JSON.parse() turns a JSON string into a real JS value. After that, we can read its properties.

const text = '{"name":"Neha","age":22,"courses":["JS","TS"]}';
const student = JSON.parse(text);

console.log(student);            // { name: 'Neha', age: 22, courses: [ 'JS', 'TS' ] }
console.log(student.courses[1]); // TS
console.log(typeof student);     // object

2.8 Reading an API Response

An API response body comes as JSON text. We parse it and then check values like status code and email.

const body = '{"status":200,"data":{"id":7,"email":"amit@test.com"}}';
const response = JSON.parse(body);

console.log(response.status);     // 200
console.log(response.data.email); // amit@test.com

2.9 Invalid JSON and try/catch

If the text is not valid JSON, JSON.parse() throws a SyntaxError. We wrap it in try/catch so our test does not crash.

const badText = "{'name':'Amit'}"; // single quotes are not allowed

try {
  JSON.parse(badText);
} catch (error) {
  console.log(error.name + ": " + error.message);
}

Output

SyntaxError: Expected property name or '}' in JSON at position 1 (line 1 column 2)

2.10 Deep Copy with JSON

JSON.parse(JSON.stringify(obj)) makes a full (deep) copy. Changing the copy does not change the original, even for nested objects.

const original = { name: "Amit", address: { city: "Pune" } };
const copy = JSON.parse(JSON.stringify(original));

copy.address.city = "Delhi";
console.log(original.address.city); // Pune
console.log(copy.address.city);     // Delhi

2.11 Reading Test Data from a .json File

We keep test data in a file like users.json. We can read it with fs.readFileSync() plus JSON.parse(), or load it directly with require(). Here, both files are in the same folder, and we run node test.js from that folder.

// users.json
{
  "baseUrl": "https://test.example.com",
  "users": [
    { "username": "amit", "password": "Amit@123", "role": "admin" },
    { "username": "neha", "password": "Neha@123", "role": "student" }
  ]
}
// test.js
const fs = require("fs");

// Way 1: read text, then parse
const data = JSON.parse(fs.readFileSync("./users.json", "utf8"));
console.log(data.users.length);      // 2
console.log(data.users[0].username); // amit

// Way 2: require parses it for us
const config = require("./users.json");
console.log(config.baseUrl);         // https://test.example.com

2.12 Looping Over Test Data

Once the data is parsed, we can loop over it and run the same check for each user.

const data = require("./users.json");

for (const user of data.users) {
  console.log(`${user.username} - ${user.role}`);
}

Output

amit - admin
neha - student

3. Interview Questions and Answers

Q1. What is JSON?

JSON stands for JavaScript Object Notation. It is a simple text format used to store and send data. It is easy for people to read and easy for programs to process.

It is used almost everywhere in test automation. REST APIs send request and response bodies as JSON, and test data like users, URLs and config values is often kept in .json files.

Q2. What is the difference between a JSON and a JavaScript object?

A JavaScript object is a real value in memory. It can hold functions, undefined, dates and more. JSON is only text, a string that describes data.

JSON also has stricter rules. Keys must be in double quotes, strings must use double quotes, and comments and trailing commas are not allowed. So { name: 'Amit' } is a valid JS object but not valid JSON, while {"name":"Amit"} is valid JSON.

Q3. Which data types are allowed in JSON?

JSON supports only six types: string, number, boolean, null, object and array. Objects and arrays can be nested inside each other.

Values like undefined, functions, NaN, Infinity and Date objects are not part of JSON. When they are stringified, they are removed, turned into null, or turned into a string, as with dates.

Q4. What does JSON.stringify() do?

JSON.stringify() converts a JavaScript value, like an object or array, into a JSON string. The result is always of type string.

It is used when data must be sent as text, for example in an API request body, or when data must be saved to a file or printed in a log.

Q5. What does JSON.parse() do?

JSON.parse() does the opposite of stringify. It takes a JSON string and turns it into a real JavaScript value, usually an object or an array.

After parsing, properties can be read normally, like response.data.email. This is the usual step before checking values in an API response.

Q6. What happens if JSON.parse() gets invalid JSON, and how is it handled?

It throws a SyntaxError. Common causes are single quotes, keys without quotes, a trailing comma, or an empty string. For an empty string, the message is Unexpected end of JSON input.

The call is placed inside a try...catch block. In the catch block, the error can be logged or the test can be failed with a clear message, so the whole run does not crash.

Q7. What does JSON.stringify() do with undefined, functions and NaN?

Inside an object, keys whose value is undefined or a function are simply left out. Inside an array, these values become null, because array positions must stay in place.

NaN and Infinity become null. So JSON.stringify({ n: NaN }) gives {"n":null}. This matters when a request body has missing values, because those keys may silently disappear.

Q8. What are the second and third arguments of JSON.stringify()?

The second argument is called the replacer. It can be an array of key names to keep, like ["name", "age"], or a function that changes values. When it is not needed, null is passed.

The third argument is the space value used for indentation. JSON.stringify(user, null, 2) prints the JSON on many lines with 2 spaces, which makes logs and saved files much easier to read.

Q9. How can sensitive data like a password be hidden when logging an object?

A replacer array can be passed to JSON.stringify() with only the safe keys. For example, JSON.stringify(user, ["name", "age"]) keeps only name and age, and the password is not printed.

This is useful in test logs and reports, where passwords or tokens should never be shown.

Q10. How can an object be deep copied using JSON, and what are its limits?

JSON.parse(JSON.stringify(obj)) creates a completely new object, including new nested objects. Changes to the copy do not affect the original. A spread copy like { ...obj } copies only the top level, so nested objects are still shared.

The limits come from JSON rules. Functions and undefined values are lost, and a Date becomes a string like "2026-01-15T10:30:00.000Z". It works well for plain test data like users and payloads.

Q11. How is test data read from a .json file in Node.js?

One way is fs.readFileSync("./users.json", "utf8"), which returns the file content as a string. That string is then passed to JSON.parse() to get an object.

Another way is require("./users.json"). Node reads and parses the file in one step and returns the object directly.

Q12. What is the difference between require() and fs.readFileSync() for JSON files?

require() parses the file and caches it. If the same file is required again in the same run, Node returns the cached object, so changes made to the file during the run are not seen. The path is also relative to the current code file.

fs.readFileSync() reads the file fresh every time, and the result must be parsed with JSON.parse(). Its relative path is based on the folder where Node was started. It is a better choice when the file can change during the run.

Q13. Can two objects be compared using JSON.stringify()?

Yes, for simple cases. Objects cannot be compared with ===, because { a: 1 } === { a: 1 } is false (they are two different objects in memory). Comparing their JSON strings checks the content instead.

The weak point is key order. JSON.stringify({ a: 1, b: 2 }) === JSON.stringify({ b: 2, a: 1 }) is false, even though the data is the same. So this trick is safe only when the key order is known to be the same.

Q14. Why is JSON so important in API test automation?

Most REST APIs use JSON for request and response bodies. A test builds an object, stringifies it to send as the body, then parses the response to check fields like status, id or email.

JSON files also keep test data separate from test code. The same test can loop over many users from one file, and the data can be changed without touching the code.

Q15. What is the output of this code?

const user = { name: "Amit", city: undefined, greet() { return "hi"; }, score: null };
console.log(JSON.stringify(user));

Output

{"name":"Amit","score":null}

The key city has the value undefined, and greet is a function. JSON has no place for these, so both keys are removed from the result.

null is a valid JSON value, so score stays as null.

Q16. What is the output of this code?

const list = [1, undefined, () => 1, null];
console.log(JSON.stringify(list));

Output

[1,null,null,null]

In arrays, values cannot just be removed, because that would shift the positions of the other items. So undefined and the function are both changed to null.

The real null stays null, and 1 stays as it is. This is different from objects, where such keys are dropped.

Q17. What is the output of this code?

const original = { name: "Amit", address: { city: "Pune" } };

const deep = JSON.parse(JSON.stringify(original));
deep.address.city = "Delhi";
console.log(original.address.city);

const shallow = { ...original };
shallow.address.city = "Mumbai";
console.log(original.address.city);

Output

Pune
Mumbai

The JSON copy is a deep copy. Its address is a brand new object, so changing it to Delhi does not touch the original, which is still Pune.

The spread copy is shallow. It copies only the top level, so shallow.address and original.address point to the same object. Changing it to Mumbai changes the original too.

Q18. What is the output of this code?

const body = '{"price":"499","qty":2}';
const order = JSON.parse(body);
console.log(order.price * order.qty);
console.log(order.price + order.qty);

Output

998
4992

In the JSON, price is in quotes, so after parsing it is the string "499", while qty is the number 2. JSON.parse keeps the types exactly as written.

The * operator turns the string into a number, so the result is 998. The + operator joins a string with a number, so it gives "4992". This is a common bug when API fields come as strings.

Q19. What is the output of this code?

const text = JSON.stringify({ id: 1 });
console.log(text.id);
console.log(JSON.parse(text).id);

Output

undefined
1

text is a string, {"id":1}, not an object. A string has no id property, so text.id is undefined.

After JSON.parse(text), the result is a real object again, so .id gives 1. This mistake happens when a response body is read as text and not parsed before checking fields.

Chapter 14: Node.js Basics

1. Overview

Node.js lets us run JavaScript outside the browser, on our own computer or a CI server. npm installs packages, and package.json stores project details. With process.env, .env, fs and path, we can manage settings, secrets, files and folders in our test projects.

2. Core Concepts

2.1 npm (Node Package Manager)

npm comes with Node.js. We use it to create a project, install packages and run scripts. Installed packages go into the node_modules folder.

npm init -y                 # create package.json with default values
npm install dotenv          # install a package (dependency)
npm install -D typescript   # install a dev-only package (devDependency)
npm uninstall dotenv        # remove a package
npm install                 # install everything listed in package.json
npm run test                # run the "test" script from package.json

2.2 package.json

package.json is the main info file of a project. It holds the name, version, scripts and the list of packages. package-lock.json saves the exact installed versions.

{
  "name": "qa-project",
  "version": "1.0.0",
  "scripts": {
    "test": "node tests/login.test.js"
  },
  "dependencies": {
    "dotenv": "^17.2.0"
  },
  "devDependencies": {
    "typescript": "^5.6.0"
  }
}

2.3 process.env

process.env is an object with all environment variables. A missing variable gives undefined. All values are strings.

// run as: TEST_ENV=staging node app.js
const env = process.env.TEST_ENV || "qa";
console.log(env);                       // staging

console.log(process.env.API_KEY);       // undefined

process.env.RETRIES = 2;
console.log(typeof process.env.RETRIES); // string

2.4 .env File with dotenv

A .env file keeps settings and secrets in KEY=value lines. The dotenv package loads them into process.env. We install it with npm install dotenv, and we never commit .env to Git.

# .env
BASE_URL=https://qa.test.com
USERNAME_QA=amit
PORT=3000
HEADLESS=true
// config.js
require("dotenv").config({ quiet: true });

console.log(process.env.BASE_URL);           // https://qa.test.com
console.log(process.env.USERNAME_QA);        // amit
console.log(process.env.PORT + 1);           // 30001
console.log(Number(process.env.PORT) + 1);   // 3001
console.log(process.env.HEADLESS === "true"); // true

{ quiet: true } stops dotenv v17 from printing its own "injecting env" log line. In ES modules, we write import "dotenv/config"; instead.

2.5 fs - Write and Read Files

fs is a built-in module for files. writeFileSync creates or replaces a file. appendFileSync adds to the end. readFileSync with "utf8" gives text.

const fs = require("fs");

fs.writeFileSync("report.txt", "Login test: PASS\n");
fs.appendFileSync("report.txt", "Logout test: FAIL\n");

const text = fs.readFileSync("report.txt", "utf8");
console.log(text);

Output

Login test: PASS
Logout test: FAIL

2.6 fs - Check, Create Folder, Delete and Errors

existsSync checks if a file exists. mkdirSync with recursive: true creates a folder safely. unlinkSync deletes a file. Reading a missing file throws an ENOENT error.

const fs = require("fs");

console.log(fs.existsSync("missing.txt"));       // false
fs.mkdirSync("screenshots", { recursive: true });
console.log(fs.existsSync("screenshots"));       // true

try {
  fs.readFileSync("missing.txt", "utf8");
} catch (e) {
  console.log(e.code);
  console.log(e.message);
}

Output

false
true
ENOENT
ENOENT: no such file or directory, open 'missing.txt'

2.7 fs - Async Reading

Sync methods block the program until they finish. fs.promises gives async versions that work with await.

const fs = require("fs");

async function readReport() {
  const data = await fs.promises.readFile("report.txt", "utf8");

3. Interview Questions and Answers

Q1. What is Node.js and why is it used in test automation?

Node.js is a runtime that runs JavaScript outside the browser. A runtime is simply the program that runs the code. It is built on Chrome's V8 engine.

Most modern JavaScript test tools run on Node.js. It is used to run test scripts, read test data files, call APIs, manage settings and run tests on CI servers.

Q2. What is npm?

npm stands for Node Package Manager. It comes with Node.js and is used to install, update and remove packages, which are ready-made code libraries.

It is also used to create a project with npm init and to run scripts with npm run. Packages are downloaded into the node_modules folder.

Q3. What is package.json?

package.json is the main config file of a Node.js project. It stores the project name, version, scripts, and the list of dependencies and devDependencies.

When another person clones the project, running npm install reads this file and installs all needed packages. It is created with npm init -y.

Q4. What is the difference between dependencies and devDependencies?

dependencies are packages needed for the app to run, installed with npm install name. devDependencies are needed only during development and testing, installed with npm install -D name.

Test tools, TypeScript and linters usually go into devDependencies. In a pure test project, most packages are often devDependencies.

Q5. What is package-lock.json and should it be committed?

package-lock.json saves the exact version of every installed package, including packages used by other packages.

Yes, it should be committed to Git. It makes sure every team member and the CI server install the same versions, so tests behave the same everywhere.

Q6. Why is node_modules not committed to Git?

node_modules is very large and can be rebuilt any time by running npm install, using package.json and package-lock.json.

So it is added to the .gitignore file. This keeps the repository small and clean.

Q7. What are npm scripts?

npm scripts are short commands saved in the "scripts" part of package.json. They are run with npm run name, like npm run test.

They save long commands under easy names, like running only smoke tests or running tests in a certain environment. npm test and npm start also work without run.

Q8. What is the difference between ^ and ~ in package versions?

Versions follow the format major.minor.patch, like 17.2.0. The caret ^17.2.0 allows newer minor and patch updates, like 17.3.1, but not 18.0.0.

The tilde ~17.2.0 allows only patch updates, like 17.2.5. A version with no symbol installs exactly that version.

Q9. What is process.env?

process.env is a built-in object that holds all environment variables. Environment variables are settings given to a program from outside the code, like TEST_ENV=staging.

It is used to switch environments, browsers or URLs without changing code. A missing variable gives undefined, so a default is often added, like process.env.TEST_ENV || "qa".

Q10. What type are the values in process.env?

All values in process.env are strings. Even if a number is assigned, like process.env.RETRIES = 2, it is stored as the string "2".

So numbers must be changed with Number(), and booleans must be compared as text, like process.env.HEADLESS === "true". Comparing with the real true gives false.

Q11. What is a .env file and what does dotenv do?

A .env file is a simple text file with settings in KEY=value lines, like base URLs, usernames and passwords.

The dotenv package reads this file and puts the values into process.env. It is loaded once at the start with require("dotenv").config(). By default, it does not overwrite variables that are already set in the system.

Q12. Why should .env not be committed to Git?

The .env file often has secrets like passwords, tokens and API keys. Committing it would share these secrets with everyone who can see the repository.

So .env is added to .gitignore. Teams often commit a .env.example file with key names but no real values. On CI servers, secrets are set as environment variables instead.

Q13. What is the fs module used for?

fs stands for file system. It is a built-in module used to read, write, append, check and delete files and folders.

In test automation, it is used to read test data, write reports or logs, create screenshot folders and clean up old files. Common methods are readFileSync, writeFileSync, appendFileSync, existsSync and mkdirSync.

Q14. What is the difference between readFileSync and fs.promises.readFile?

readFileSync is synchronous. It blocks the program until the whole file is read. It is simple and fine for small files at test setup.

fs.promises.readFile is asynchronous and returns a Promise, so it is used with await. Other work can continue while the file is read, which is better for big files or many files.

Q15. Why is the path module used instead of joining strings?

Windows uses \ in paths, and macOS and Linux use /. Joining paths with plain strings can break when tests run on a different system.

path.join uses the correct separator for the current system and cleans extra slashes and .. parts. With __dirname, it builds paths that work no matter which folder the test is started from.

Chapter 15: Dates

1. Overview

The Date object stores a date and time in JavaScript. We use it to get today's date, set future dates in forms, compare dates and make timestamps. In test automation, we use dates for booking forms, report names, unique test data and API checks.

2. Core Concepts

2.1 Creating a Date Object

We create dates with new Date(). We can pass an ISO string or year, month, day. Months start at 0, so 0 is January and 11 is December.

const d1 = new Date("2026-03-15T10:30:00Z");
console.log(d1);                // 2026-03-15T10:30:00.000Z

const d2 = new Date(2026, 0, 31);  // 31 January 2026 (local time)
console.log(d2.toDateString());    // Sat Jan 31 2026

console.log(typeof d1);            // object
console.log(new Date(0));          // 1970-01-01T00:00:00.000Z

2.2 Today's Date and Timestamps

new Date() gives the current date and time. Date.now() gives the current time in milliseconds since 1 January 1970 (UTC). The output changes every time we run it.

const today = new Date();
console.log(today);       // e.g. 2026-10-15T17:15:16.333Z (current UTC time)
console.log(Date.now());  // e.g. 1792084516333

const d = new Date("2026-03-15T10:30:00Z");
console.log(d.getTime()); // 1773570600000

2.3 Getting Parts of a Date

Getter methods return one part of the date. getMonth() is 0-based, and getDay() gives the weekday (0 = Sunday).

const d = new Date(2026, 2, 15, 10, 30, 45);  // 15 March 2026, 10:30:45

console.log(d.getFullYear());  // 2026
console.log(d.getMonth());     // 2  (March)
console.log(d.getDate());      // 15
console.log(d.getDay());       // 0  (Sunday)
console.log(d.getHours(), d.getMinutes(), d.getSeconds());  // 10 30 45

2.4 Adding or Removing Days

We use setDate(getDate() + n). JavaScript moves to the next month or year automatically. setDate changes the same object.

const d = new Date(2026, 0, 30);  // 30 January 2026
d.setDate(d.getDate() + 5);
console.log(d.toDateString());   // Wed Feb 04 2026

const nye = new Date(2026, 11, 31);
nye.setDate(nye.getDate() + 1);
console.log(nye.toDateString()); // Fri Jan 01 2027

2.5 Formatting with toISOString()

toISOString() always gives the date in UTC, in the format YYYY-MM-DDTHH:mm:ss.sssZ. We often take only the date part.

const d = new Date("2026-03-05T09:07:00Z");
console.log(d.toISOString());              // 2026-03-05T09:07:00.000Z
console.log(d.toISOString().slice(0, 10)); // 2026-03-05
console.log(d.toISOString().split("T")[0]); // 2026-03-05

2.6 Custom Format (DD/MM/YYYY)

We build our own format with getters and padStart. We add 1 to the month because it starts at 0.

const d = new Date(2026, 2, 5);  // 5 March 2026

const dd = String(d.getDate()).padStart(2, "0");
const mm = String(d.getMonth() + 1).padStart(2, "0");
const yyyy = d.getFullYear();

console.log(`${dd}/${mm}/${yyyy}`);  // 05/03/2026
console.log(`${yyyy}-${mm}-${dd}`);  // 2026-03-05

2.7 Formatting with toLocaleDateString()

toLocaleDateString formats a date for a country (locale). Options let us show the full month name or weekday.

const d = new Date(2026, 2, 5, 9, 7);  // 5 March 2026, 09:07

console.log(d.toLocaleDateString("en-US"));  // 3/5/2026
console.log(d.toLocaleDateString("en-GB"));  // 05/03/2026
console.log(d.toLocaleDateString("en-IN"));  // 5/3/2026
console.log(d.toLocaleDateString("en-US", { year: "numeric", month: "long", day: "numeric" }));  // March 5, 2026
console.log(d.toLocaleDateString("en-US", { weekday: "long" }));  // Thursday
console.log(d.toLocaleTimeString("en-US"));  // 9:07:00 AM
console.log(d.toDateString());               // Thu Mar 05 2026

2.8 Comparing Dates and Finding the Difference

Subtracting two dates gives the difference in milliseconds. We divide by 1000 * 60 * 60 * 24 to get days. > and < work directly on dates.

const start = new Date("2026-03-01T00:00:00Z");
const end = new Date("2026-03-15T00:00:00Z");

console.log(end - start);                          // 1209600000
console.log((end - start) / (1000 * 60 * 60 * 24)); // 14
console.log(end > start);                          // true

2.9 Invalid Dates

A wrong date string gives an "Invalid Date". getTime() then returns NaN, and toISOString() throws an error.

const bad = new Date("hello");
console.log(bad);                 // Invalid Date
console.log(bad.getTime());       // NaN
console.log(isNaN(bad));          // true
bad.toISOString();

Output

Invalid Date
NaN
true
RangeError: Invalid time value

3. Interview Questions and Answers

Q1. What is the Date object in JavaScript?

The Date object stores one moment in time. Inside, it keeps a single number: the milliseconds passed since 1 January 1970, 00:00:00 UTC. This starting point is called the Unix epoch.

It has methods to read parts like year and month, change them, compare dates and format them as text. In testing, it is used for form dates, timestamps, report names and checking dates in API responses.

Q2. What are the different ways to create a Date?

new Date() gives the current date and time. new Date("2026-03-15T10:30:00Z") creates a date from an ISO string. new Date(2026, 2, 15) creates a date from numbers in local time.

new Date(milliseconds) creates a date from a timestamp, like new Date(0) for 1 January 1970. Copying a date is done with new Date(oldDate).

Q3. Why does getMonth() return 2 for March?

In JavaScript, months are 0-based. January is 0, February is 1, March is 2, and December is 11.

So, to show the real month number, 1 is added, like getMonth() + 1. The same rule applies when creating a date: new Date(2026, 2, 15) means 15 March, not February.

Q4. What is the difference between getDate() and getDay()?

getDate() returns the day of the month, from 1 to 31.

getDay() returns the day of the week, from 0 to 6, where 0 is Sunday and 6 is Saturday. Mixing these two up is a very common bug.

Q5. What is the difference between new Date() and Date.now()?

new Date() returns a full Date object, with methods like getFullYear() and toISOString().

Date.now() returns only a number, the current time in milliseconds. It is faster and is commonly used to measure how long a step takes or to make unique test data, like user_1792084516333@test.com.

Q6. What is a timestamp and how is it read?

A timestamp is the number of milliseconds since 1 January 1970 UTC. It is one simple number, so it is easy to store, compare and send in APIs.

It is read from a date with getTime(), like d.getTime(). A timestamp can be changed back to a date with new Date(timestamp). Some APIs use seconds instead of milliseconds, so the value may need to be multiplied by 1000.

Q7. How can today's date be formatted as YYYY-MM-DD?

A quick way is new Date().toISOString().slice(0, 10). But toISOString() uses UTC, so near midnight it can show the previous or next day compared to local time.

For the local date, the parts are built with getFullYear(), getMonth() + 1 and getDate(), and padStart(2, "0") adds a leading zero to single digits.

Q8. What does toISOString() return?

toISOString() returns the date as a string in ISO 8601 format, like 2026-03-05T09:07:00.000Z. ISO 8601 is the standard international date format.

It is always in UTC, shown by the Z at the end. Most APIs send and expect dates in this format. JSON.stringify also uses it when saving a Date.

Q9. What is the difference between UTC and local time?

UTC is the world standard time with no time zone offset. Local time is the time in the time zone of the computer running the code, like India time, which is UTC+5:30.

Methods like getHours() use local time, and methods like getUTCHours() use UTC. Tests can give different results on a local laptop and a CI server in another time zone, so UTC is safer for comparisons.

Q10. How is a date string like "2026-03-15" treated compared to "2026-03-15T10:00:00"?

A date-only ISO string, like "2026-03-15", is treated as UTC midnight. In a time zone behind UTC, like New York, getDate() can then show 14 instead of 15.

A date-time string without Z, like "2026-03-15T10:00:00", is treated as local time. Adding Z or an offset like +05:30 makes the meaning clear and avoids such bugs.

Q11. How can days be added to a date?

The common way is d.setDate(d.getDate() + n). A negative n goes back in time. JavaScript handles the end of month and end of year automatically.

setDate changes the original Date object. If the original is still needed, a copy is made first with new Date(d). This is used in tests to pick a check-in date like "today + 7 days".

Q12. How are two dates compared?

> and < work directly, because dates are changed into their timestamps for these checks.

But === compares object references, not values, so two dates with the same time give false. For equality, timestamps are compared, like a.getTime() === b.getTime().

Q13. How is the number of days between two dates found?

Subtracting two dates, like end - start, gives the difference in milliseconds. Dividing by 1000 * 60 * 60 * 24, which is milliseconds in one day, gives the number of days.

Math.round is often added, because daylight saving time can make a day 23 or 25 hours long in local time.

Q14. What is an Invalid Date and how is it checked?

An Invalid Date is a Date object created from a value that cannot be read as a date, like new Date("hello"). It prints "Invalid Date", and getTime() returns NaN.

It is checked with isNaN(d.getTime()) or isNaN(d). Calling toISOString() on it throws RangeError: Invalid time value, so dates from user input or APIs should be checked first.

Q15. How can the last day of a month be found?

Day 0 of a month means the last day of the month before. So new Date(year, month + 1, 0) gives the last day of month.

For example, new Date(2024, 2, 0).getDate() gives 29, because 2024 is a leap year and February has 29 days. This trick is useful to test month-end and leap-year cases in date pickers.

Q16. What is the output of this Date parts code?

console.log(d.getFullYear(), d.getMonth(), d.getDate(), d.getDay());

Output

2026 0 31 6

Month 0 means January, so the date is 31 January 2026. getMonth() returns 0, not 1.

getDate() returns the day of the month, 31. getDay() returns the weekday, and 31 January 2026 is a Saturday, which is 6.

Q18. What is the output when two dates are compared?

Subtracting dates changes them into timestamps, so the result is the gap in milliseconds: 14 days × 86,400,000 = 1209600000.

Dividing by the milliseconds in one day gives 14. end > start is true, because the later date has the bigger timestamp.

Chapter 16: Math & Random Data

1. Overview

The built-in Math object gives ready-made functions for numbers, like rounding, finding the max or min, and making random numbers. In test automation, we use it to round prices, check totals, and create random or unique test data. Unique data, like a new email for each run, stops tests from failing because of duplicate values.

2. Core Concepts

2.1 Math.floor() - Round Down

Math.floor() always goes down to the nearest whole number. For negative numbers, "down" means further from zero.

console.log(Math.floor(4.9));  // 4
console.log(Math.floor(-4.2)); // -5

2.2 Math.ceil() - Round Up

Math.ceil() always goes up to the nearest whole number. It is useful for counting pages.

console.log(Math.ceil(4.1));  // 5
console.log(Math.ceil(-4.8)); // -4

const totalUsers = 23;
const perPage = 5;
console.log(Math.ceil(totalUsers / perPage)); // 5

2.3 Math.round() - Nearest Whole Number

Math.round() goes to the nearest whole number. If the decimal part is exactly .5, it goes up (towards the bigger number).

console.log(Math.round(4.4));  // 4
console.log(Math.round(4.5));  // 5
console.log(Math.round(-2.5)); // -2
console.log(Math.round(-2.6)); // -3

2.4 Math.trunc() - Remove Decimals

Math.trunc() just cuts off the decimal part. It does not round.

console.log(Math.trunc(4.9));  // 4
console.log(Math.trunc(-4.9)); // -4

2.5 Math.max(), Math.min() and Math.abs()

Math.max() and Math.min() return the biggest and smallest of the given numbers. For an array, we use the spread .... Math.abs() removes the minus sign.

const scores = [72, 95, 64];

console.log(Math.max(...scores)); // 95
console.log(Math.min(...scores)); // 64
console.log(Math.abs(-15));       // 15

2.6 Rounding to 2 Decimals

Prices often need 2 decimals. toFixed(2) returns a string. Math.round(x * 100) / 100 returns a number.

const price = 199.567;

console.log(price.toFixed(2));                 // 199.57
console.log(typeof price.toFixed(2));          // string
console.log(Math.round(price * 100) / 100);    // 199.57
console.log(0.1 + 0.2);                        // 0.30000000000000004
console.log((0.1 + 0.2).toFixed(2));           // 0.30

2.7 Math.random()

Math.random() returns a random decimal from 0 up to (but not including) 1. The value changes on every run.

console.log(Math.random());      // random, e.g. 0.18687890635146265
console.log(Math.random() * 10); // random, e.g. 7.401845872571603

2.8 Random Whole Number in a Range

We multiply Math.random(), then use Math.floor() to get a whole number. The formula below gives a number from min to max, both included.

function randomInt(min, max) {
  return Math.floor(Math.random() * (max - min + 1)) + min;
}

console.log(randomInt(1, 6));    // random 1 to 6, e.g. 4
console.log(randomInt(18, 60));  // random 18 to 60, e.g. 35

2.9 Random Item from an Array

A random index from 0 to length - 1 picks a random item.

const browsers = ["chromium", "firefox", "webkit"];
const index = Math.floor(Math.random() * browsers.length);

console.log(browsers[index]); // random, e.g. webkit

2.10 Random String

toString(36) turns a random number into letters and digits. slice(2, 8) removes the "0." part and keeps 6 characters.

const code = Math.random().toString(36).slice(2, 8);
console.log(code); // random, e.g. 114yxo

2.11 Unique Test Data with Date.now()

Date.now() gives the current time in milliseconds. It changes every run, so it is good for unique emails and usernames.

const email = `user_${Date.now()}@test.com`;
const username = `student_${Math.floor(Math.random() * 10000)}`;

console.log(email);    // e.g. user_1792084648775@test.com
console.log(username); // e.g. student_4821

2.12 Unique ID with crypto.randomUUID()

Node.js has a built-in crypto.randomUUID(). It gives a 36-character ID that is almost never repeated.

const orderId = crypto.randomUUID();

console.log(orderId);        // e.g. 55fde837-74b0-49ba-b0f5-bcf8b2df13ed
console.log(orderId.length); // 36

2.13 Random Phone Number and OTP

We build fixed-length numbers with randomInt(). padStart() adds zeros in front so the length stays the same.

function randomInt(min, max) {
  return Math.floor(Math.random() * (max - min + 1)) + min;
}

const phone = "9" + randomInt(100000000, 999999999);
const otp = String(randomInt(0, 9999)).padStart(4, "0");

console.log(phone); // e.g. 9482039175
console.log(otp);   // e.g. 0007

3. Interview Questions and Answers

Q1. What is the Math object in JavaScript?

Math is a built-in object that holds ready-made number functions and constants, like Math.round(), Math.max(), Math.random() and Math.PI.

It is not a class, so no object is created with new. All its functions are called directly on Math, for example Math.floor(4.9).

Q2. What is the difference between Math.floor(), Math.ceil(), Math.round() and Math.trunc()?

Math.floor() always rounds down and Math.ceil() always rounds up. Math.round() goes to the nearest whole number, and .5 goes up. Math.trunc() just cuts the decimal part off.

For positive numbers, floor and trunc give the same result. For negative numbers they differ: Math.floor(-4.2) is -5, but Math.trunc(-4.2) is -4.

Q3. What does Math.random() return?

It returns a random decimal number from 0 up to, but not including, 1. So 0 is possible but 1 is never returned.

It takes no arguments. To get a bigger range, the result is multiplied, for example Math.random() * 10 gives a decimal from 0 up to (but not including) 10.

Q4. How is a random whole number between min and max generated?

The common formula is Math.floor(Math.random() * (max - min + 1)) + min. It gives a whole number from min to max, both included.

The + 1 is important. Without it, max can never be returned. For a dice roll, Math.floor(Math.random() * 6) + 1 gives 1 to 6.

Q5. Why is Math.floor() used with Math.random() and not Math.round()?

Math.floor() gives every number in the range the same chance. Each whole number gets an equal slice of the random range.

With Math.round(), the first and last numbers get only half a slice. For example, Math.round(Math.random() * 10) gives 0 and 10 much less often than 1 to 9, so the data is not evenly random.

Q6. How is a random item picked from an array?

A random index is made with Math.floor(Math.random() * arr.length). This gives a number from 0 to length - 1, which are exactly the valid indexes.

Then the item is read with arr[index]. This is useful for picking a random browser, role, city or course name in test data.

Q7. Why is unique test data needed in automation?

Many apps do not allow duplicate values, like the same email or username on sign-up. If a test uses a fixed email, it passes once and then fails on the next run with "user already exists".

Unique data makes each run independent. Tests can run again and again, and also in parallel, without clashing with old data.

Q8. How is a unique email created for each test run?

A common way is to add a timestamp, like `user_${Date.now()}@test.com`. Date.now() returns the milliseconds since 1 January 1970, so it changes every millisecond.

When tests run in parallel, two tests can hit the same millisecond. To be safer, a random number or crypto.randomUUID() can be added as well.

Q9. What is crypto.randomUUID()?

It is a built-in function in Node.js that returns a UUID, a random 36-character ID like 55fde837-74b0-49ba-b0f5-bcf8b2df13ed. No package needs to be installed.

The chance of two UUIDs being the same is extremely small, so it is a strong choice for order IDs, request IDs and unique names in tests.

Q10. Is Math.random() safe for passwords or security tokens?

No. Math.random() is not cryptographically secure. Its numbers can, in theory, be predicted, so it should not be used for real passwords, tokens or secret keys.

For test data like names, ages and emails, it is fine. For anything security-related, the crypto module, such as crypto.randomUUID(), is the better choice.

Q11. How are the max and min values found in an array?

Math.max() and Math.min() take separate numbers, not an array. So the array is spread into them, like Math.max(...scores).

Passing the array directly, like Math.max(scores), gives NaN. An empty array spread into Math.max() gives -Infinity.

Q12. How is a price rounded to 2 decimals, and what is the difference between toFixed() and Math.round()?

price.toFixed(2) returns a string like "199.57". It is good for showing values or comparing with text on a page.

Math.round(price * 100) / 100 returns a number like 199.57. It is better when the value is used in more maths, like adding a cart total.

Q13. Why does 0.1 + 0.2 not equal 0.3 in JavaScript?

Numbers are stored in binary, and some decimals like 0.1 and 0.2 cannot be stored exactly. So 0.1 + 0.2 becomes 0.30000000000000004, and 0.1 + 0.2 === 0.3 is false.

In tests that check prices or totals, values are rounded first, for example with toFixed(2), and then compared. This avoids false failures.

Q14. What is the output of this code?

console.log(Math.round(4.5));
console.log(Math.round(2.5));
console.log(Math.round(-2.5));
console.log(Math.round(-2.6));

Output

5
3
-2
-3

For an exact .5, Math.round() always goes up, towards the bigger number. So 4.5 becomes 5 and 2.5 becomes 3.

For -2.5, the bigger number is -2, so the result is -2, not -3. For -2.6, the nearest whole number is -3, so it becomes -3.

Q15. What is the output of this code?

console.log(Math.floor(-4.2));
console.log(Math.trunc(-4.9));
console.log(Math.ceil(-4.8));
console.log(Math.floor(4.9));

Output

-5
-4
-4
4

Math.floor() goes down. For -4.2, down means more negative, so it becomes -5. For 4.9, down is 4.

Math.trunc(-4.9) just removes the decimal, giving -4. Math.ceil(-4.8) goes up, towards zero, so it is also -4.

Q16. What is the output of this code?

const scores = [72, 95, 64];

console.log(Math.max());
console.log(Math.min());
console.log(Math.max(scores));
console.log(Math.max(...scores));

Output

-Infinity
Infinity
NaN
95

With no arguments, Math.max() starts from the smallest possible value, -Infinity, and Math.min() starts from Infinity. Nothing is there to compare, so these start values are returned.

Math.max(scores) gets one array, not numbers, and the array cannot become a single number, so the result is NaN. With the spread ...scores, the numbers are passed one by one, and 95 is returned.

Q17. What is the output of this code?

const total = 0.1 + 0.2;

console.log(total);
console.log(total === 0.3);
console.log(total.toFixed(2));
console.log(typeof total.toFixed(2));

Output

0.30000000000000004
false
0.30
string

Because 0.1 and 0.2 are not stored exactly in binary, the sum has a tiny extra part. That is why the strict check with 0.3 is false.

toFixed(2) rounds to 2 decimals and gives 0.30. Its type is string, not number, so it must be compared with a string like "0.30".

Q18. What is the output of this code?

console.log(Math.max(1, "5"));
console.log(Math.max(1, "a"));
console.log(Math.round("4.6"));
console.log(Math.floor(null));

Output

5
NaN
5
0

Math functions first turn every value into a number. The string "5" becomes 5, so the max is 5. The string "4.6" becomes 4.6, which rounds to 5.

The string "a" cannot become a number, so it turns into NaN, and any maths with NaN gives NaN. null turns into 0, so Math.floor(null) is 0. This matters when values from a page or API come as strings.

Chapter 17: Regular Expressions

1. Overview

A regular expression (regex) is a pattern that describes what text should look like. We use it to check formats, like email or phone number, and to pull values out of text, like an order ID or a count. In test automation, regex helps us check dynamic text where some parts change on every run.

2. Core Concepts

2.1 Creating a Regex

We can write a regex between two slashes, or use new RegExp() with a string. Both make the same pattern. Its type is object.

const r1 = /test/;
const r2 = new RegExp("test");

console.log(r1);        // /test/
console.log(r2);        // /test/
console.log(typeof r1); // object

2.2 Flags: i and g

Flags are letters added after the last slash. i ignores upper and lower case. g (global) finds all matches, not just the first.

const text = "Is this all there is?";

console.log(text.match(/is/g));  // [ 'is', 'is' ]
console.log(text.match(/is/gi)); // [ 'Is', 'is', 'is' ]

2.3 test() - Does It Match?

regex.test(text) returns true or false. It is the simplest way to check a pattern in an assertion.

const message = "Login successful";

console.log(/login/.test(message));  // false
console.log(/login/i.test(message)); // true

2.4 match() - Get the Matched Text

text.match(regex) returns the matched part. Without g, it gives the first match with extra details. With g, it gives an array of all matches. If nothing matches, it returns null.

const msg = "Order 123 placed, total 450";

console.log(msg.match(/\d+/)[0]);     // 123
console.log(msg.match(/\d+/g));       // [ '123', '450' ]
console.log("hello".match(/\d+/));    // null

Printing the full result without g shows the extra details:

console.log(msg.match(/\d+/));

Output

[
  '123',
  index: 6,
  input: 'Order 123 placed, total 450',
  groups: undefined
]

2.5 Special Characters

Some characters have a special meaning in a regex:

// \d  any digit (0-9)
// \w  letter, digit or underscore
// \s  space, tab or new line
// .   any one character
// ^   start of text
// $   end of text
// [abc]  one of a, b or c
// [^abc] any character except a, b, c
// a|b    a or b
console.log(/^\w+$/.test("user_01"));  // true
console.log(/^\w+$/.test("user-01"));  // false
console.log(/cat|dog/.test("hotdog"));  // true

2.6 Quantifiers - How Many Times

Quantifiers say how many times something can repeat.

// +      one or more
// *      zero or more
// ?      zero or one (optional)
// {3}    exactly 3
// {2,5}  2 to 5
// {8,}   8 or more
console.log(/colou?r/.test("color"));  // true
console.log(/colou?r/.test("colour")); // true
console.log(/^\d{6}$/.test("411001"));  // true

2.7 Escaping Special Characters

To match a real dot, slash or similar character, we put a backslash before it. . means "any character", but \. means a real dot.

console.log(/a.c/.test("abc"));   // true
console.log(/a\.c/.test("abc"));  // false
console.log(/a\.c/.test("a.c"));  // true
console.log(/^https:\/\//.test("https://test.example.com")); // true

2.8 Groups ( ) - Extract Parts

Round brackets capture a part of the match. [0] is the full match, and [1], [2] ... are the groups.

const m = "2026-10-15".match(/(\d{4})-(\d{2})-(\d{2})/);

console.log(m[0]); // 2026-10-15
console.log(m[1]); // 2026
console.log(m[2]); // 10
console.log(m[3]); // 15

2.9 replace() with Regex

A regex in replace() lets us clean text. Without g, only the first match is replaced.

console.log("a-b-c".replace(/-/, " "));   // a b-c
console.log("a-b-c".replace(/-/g, " "));  // a b c
console.log("  too   many   spaces ".trim().replace(/\s+/g, " ")); // too many spaces

2.10 Common Pattern: Email

A simple email check: some text, then @, then a domain with a dot.

const emailRe = /^[^\s@]+@[^\s@]+\.[^\s@]+$/;

console.log(emailRe.test("amit@test.com"));   // true
console.log(emailRe.test("amit@test"));       // false
console.log(emailRe.test("amit test@x.com")); // false

2.11 Common Pattern: Phone, PIN and Date

^ and $ make sure the whole text matches, not just a part of it.

const phoneRe = /^\d{10}$/;
const dateRe = /^\d{4}-\d{2}-\d{2}$/;

console.log(phoneRe.test("9876543210"));  // true
console.log(phoneRe.test("98765"));       // false
console.log(dateRe.test("2026-10-15"));   // true
console.log(dateRe.test("15-10-2026"));   // false

2.12 Common Pattern: Password Rule

This pattern checks: at least 8 characters, at least one capital letter and at least one digit. (?=...) means "this must appear somewhere ahead".

const passRe = /^(?=.*[A-Z])(?=.*\d).{8,}$/;

console.log(passRe.test("Amit@123")); // true
console.log(passRe.test("amit1234")); // false

2.13 Extracting Values from UI Text

Pages often show dynamic text. We use regex to pull out the number or ID we need.

const info = "Showing 1-10 of 245 results";
const price = "Price: $1,299.50";
const orderText = "Order ID: ORD-4521";

console.log(info.match(/of (\d+)/)[1]);                 // 245
console.log(Number(price.replace(/[^\d.]/g, "")));     // 1299.5
console.log(orderText.match(/ORD-\d+/)[0]);            // ORD-4521

3. Interview Questions and Answers

Q1. What is a regular expression?

A regular expression, or regex, is a pattern used to search, check or change text. It describes the shape of the text, like "10 digits" or "text, then @, then a domain".

In testing, it is used to check formats like email, phone and date, and to pull values like an order ID or total count out of a message on the page.

Q2. What are the two ways to create a regex in JavaScript?

The first way is a regex literal, written between slashes, like /test/i. It is short and used when the pattern is fixed.

The second way is new RegExp("test", "i"). It is used when the pattern is built from a variable, for example a username coming from test data. In a string, a backslash must be written twice, so \d becomes "\\d".

Q3. What is the difference between test() and match()?

test() is called on the regex, like /\d+/.test(text), and returns only true or false. It is best for yes/no checks in assertions.

match() is called on the string, like text.match(/\d+/), and returns the matched text in an array, or null if nothing matches. It is used when the actual value is needed.

Q4. What do the g and i flags do?

The i flag makes the match case-insensitive, so /login/i matches "Login", "LOGIN" and "login".

The g flag means global. With match(), it returns all matches instead of only the first. With replace(), it replaces every match instead of only the first one.

Q5. What do ^ and $ mean, and why are they important for validation?

^ means the start of the text and $ means the end. Together they force the whole text to match the pattern.

Without them, a part of the text can match. For example, /\d{10}/ returns true for an 11-digit number, because 10 of its digits match. /^\d{10}$/ correctly returns false.

Q6. What do \d, \w, \s and . mean?

\d matches one digit from 0 to 9. \w matches a letter, digit or underscore. \s matches a space, tab or new line.

The dot . matches any single character except a new line. The capital versions mean the opposite, so \D is "not a digit" and \S is "not a space".

Q7. What is the difference between +, * and ?

+ means one or more times, * means zero or more times, and ? means zero or one time, so the item is optional.

For example, /\d+/ needs at least one digit, and /colou?r/ matches both "color" and "colour". Curly brackets give exact counts, like {6} for exactly 6.

Q8. How is a special character like a dot matched literally?

A backslash is put before it. This is called escaping. \. matches a real dot, while . alone matches any character.

This matters for URLs, emails and prices. Characters that usually need escaping are . * + ? ^ $ ( ) [ ] { } | \ /.

Q9. What are capture groups and how are they used?

Capture groups are parts of a pattern inside round brackets. They save the matched part separately, so it can be read later.

In the result of match(), index 0 is the full match and index 1, 2 and so on are the groups. For example, in "Showing 1-10 of 245 results", /of (\d+)/ gives "245" at index 1.

Q10. How is a regex used to check an email format in a test?

A simple pattern is /^[^\s@]+@[^\s@]+\.[^\s@]+$/. It means: some characters without spaces or @, then @, then a domain, a dot, and an ending.

It is used with test(), so it returns true or false. It is a basic check, not a full email standard check, which is enough for most UI and API tests.

Q11. How is regex useful when checking dynamic text in automation?

Many messages change every run, like "Order ORD-4521 placed" or "Last login at 10:42". An exact text check would fail each time.

A regex checks only the fixed shape, like /^Order ORD-\d+ placed$/. The test then passes for any order number but still fails if the message format is wrong.

Q12. What does match() return when there is no match, and how is it handled safely?

It returns null. Reading [0] or [1] on null throws a TypeError and stops the test.

A safe way is optional chaining with a default, like text.match(/\d+/)?.[0] ?? "none". Another way is to check the result with an if before using it.

Q13. Why can test() give different results with the g flag?

A regex with g remembers where the last match ended, in a property called lastIndex. The next test() starts searching from that position, not from the start.

So the same regex on the same text can return true, then false. For simple yes/no checks, g should not be used with test().

Q14. What is the output of this code?

const text = "Is this all there is?";

console.log(text.match(/is/g));
console.log(text.match(/is/gi));
console.log(text.match(/is/gi).length);

Output

[ 'is', 'is' ]
[ 'Is', 'is', 'is' ]
3

With only g, the search is case-sensitive. It finds "is" inside "this" and the last word "is", but not the capital "Is" at the start.

Adding i ignores case, so "Is" also matches. The array then has 3 items, so its length is 3.

Q15. What is the output of this code?

const msg = "Order 123 placed, total 450";

console.log(msg.match(/\d+/)[0]);
console.log(msg.match(/\d+/g));
console.log("hello".match(/\d+/));
console.log("Total: 5 items".match(/\d+/)[0] + 1);

Output

123
[ '123', '450' ]
null
51

Without g, only the first number is found, so [0] is "123". With g, both numbers come back in an array. "hello" has no digits, so the result is null.

The last line is a common trap. match() always returns strings, so "5" + 1 joins them into "51". It must be changed with Number() first to get 6.

Q16. What is the output of this code?

const phoneRe = /\d{10}/;
const strictRe = /^\d{10}$/;

console.log(phoneRe.test("98765432100"));
console.log(strictRe.test("98765432100"));
console.log(strictRe.test("9876543210"));

Output

true
false
true

phoneRe has no ^ and $, so it only checks if 10 digits appear somewhere. An 11-digit number contains 10 digits in a row, so it passes.

strictRe needs the whole text to be exactly 10 digits. So the 11-digit number fails and the 10-digit number passes.

Q17. What is the output of this code?

const re = /a/g;

console.log(re.test("cat"));
console.log(re.test("cat"));
console.log(re.test("cat"));

Output

true
false
true

The first call finds "a" at index 1, and lastIndex becomes 2. The second call starts at index 2, finds only "t", returns false, and resets lastIndex to 0.

The third call starts again from 0 and returns true. This is why a g regex reused in a loop can give random-looking failures.

Q18. What is the output of this code?

const price = "Price: $1,299.50";
const clean = price.replace(/[^\d.]/g, "");

console.log(clean);
console.log(Number(clean));
console.log("a-b-c".replace(/-/, " "));
console.log("a-b-c".replace(/-/g, " "));

Output

1299.50
1299.5
a b-c
a b c

[^\d.] means "anything that is not a digit or a dot". With g, all those characters are removed, so the text, the $ sign and the comma go away, leaving "1299.50".

Number() turns it into 1299.5, because a number drops the extra trailing zero. In the last two lines, without g, only the first dash is replaced. With g, both dashes are replaced.

Chapter 18: TypeScript Basics

1. Overview

TypeScript is JavaScript with types added. The TypeScript compiler (tsc) checks our code for type mistakes before it runs, then turns it into plain JavaScript. Most modern test automation projects use TypeScript because it catches bugs early and gives better auto-complete in the editor.

2. Core Concepts

2.1 JS vs TS Differences

TypeScript files end with .ts. Types are checked at compile time (before running), and then removed. Node.js and browsers always run the plain JavaScript output.

// JavaScript: no error until the code runs
let age = 25;
age = "twenty five";  // allowed in JS

// TypeScript: error before running
let count: number = 25;
count = "twenty five";

Output (tsc)

error TS2322: Type 'string' is not assignable to type 'number'.

2.2 Installing TypeScript and Using tsc

We install TypeScript as a dev dependency. tsc compiles .ts files into .js files.

npm install -D typescript     # install
npx tsc --version             # check version
npx tsc --init                # create tsconfig.json
npx tsc login.ts              # compile one file -> login.js
node login.js                 # run the output
npx tsc                       # compile the whole project using tsconfig.json
npx tsc --noEmit              # only check types, create no .js files

2.3 Type Annotations

We add a type after a colon. TypeScript can also guess the type from the value. This is called type inference.

let userName: string = "Amit";
let age: number = 25;
let isActive: boolean = true;
let browsers: string[] = ["chrome", "firefox"];
let codes: Array<number> = [200, 404];
let id: string | number = 101;   // union: string OR number
id = "A101";

let course = "TypeScript";       // inferred as string
console.log(userName, age, isActive, browsers, codes, id);

Output

Amit 25 true [ 'chrome', 'firefox' ] [ 200, 404 ] A101

2.4 Function Types

We give types to parameters and to the return value. void means the function returns nothing.

function add(a: number, b: number): number {
  return a + b;
}
function logStep(step: string): void {
  console.log("Step:", step);
}
console.log(add(2, 3));    // 5
logStep("Open login page"); // Step: Open login page

add(2, "3");
add(2);

Output (tsc)

error TS2345: Argument of type 'string' is not assignable to parameter of type 'number'.
error TS2554: Expected 2 arguments, but got 1.

2.5 any and unknown

any turns off type checking. unknown accepts any value, but we must check the type before using it.

let data: any = 42;
data.toUpperCase();   // no tsc error, but crashes at runtime

let value: unknown = "hello";
value.toUpperCase();  // tsc error
if (typeof value === "string") {
  console.log(value.toUpperCase());  // HELLO
}

Output

tsc:     error TS18046: 'value' is of type 'unknown'.
runtime: TypeError: data.toUpperCase is not a function

In TypeScript, unknown is a type-safe alternative to any. It tells TypeScript: "This variable could hold literally any type of data, so I cannot assume it is a string, a number, an object, etc." Because TypeScript doesn't know for sure that value is a string on line 3, it prevents you from calling string methods like .toUpperCase() until you perform type checking or type narrowing.

2.6 Optional Parameters (?)

A ? after a parameter name makes it optional. Its type becomes "the type or undefined". Optional parameters must come after required ones.

function greet(name: string, title?: string): string {
  return title ? `Hello, ${title} ${name}` : `Hello, ${name}`;
}
console.log(greet("Amit"));         // Hello, Amit
console.log(greet("Amit", "Mr."));  // Hello, Mr. Amit

function shout(title?: string) {
  return title.toUpperCase();
}

Output (tsc)

error TS18048: 'title' is possibly 'undefined'.

2.7 type vs interface

Both describe the shape of an object. ? marks an optional property. type can also name unions. interface can use extends.

type User = { name: string; age: number; email?: string };
type Status = "pass" | "fail" | "skip";

interface Student { name: string; course: string }
interface Topper extends Student { rank: number }

const u: User = { name: "Amit", age: 25 };
const t: Topper = { name: "Riya", course: "JS", rank: 1 };
const s: Status = "pass";
console.log(u, t, s);

const bad: User = { name: "Karan" };

Output

tsc: error TS2741: Property 'age' is missing in type '{ name: string; }' but required in type 'User'.
{ name: 'Amit', age: 25 } { name: 'Riya', course: 'JS', rank: 1 } pass

2.8 Enums

An enum is a named set of fixed values. Numeric enums start at 0. String enums are clearer for things like environments.

enum Role {
  Admin,
  Tester,
  Developer,
}
enum Env {
  QA = "qa",
  Staging = "staging",
}
console.log(Role.Admin, Role.Tester);  // 0 1
console.log(Role[1]);                  // Tester
console.log(Env.QA);                   // qa

2.9 Access Modifiers

public is open to all (default). private is only for the class. protected is for the class and its child classes. readonly cannot be changed after it is set.

class Account {
  public owner: string;
  private balance: number;
  protected type: string = "savings";
  readonly id: number = 1;
  constructor(owner: string, balance: number) {
    this.owner = owner;
    this.balance = balance;
  }
  getBalance(): number {
    return this.balance;
  }
}
const acc = new Account("Amit", 500);
console.log(acc.owner, acc.getBalance());  // Amit 500
acc.balance;
acc.type;
acc.id = 2;

Output (tsc)

error TS2341: Property 'balance' is private and only accessible within class 'Account'.
error TS2445: Property 'type' is protected and only accessible within class 'Account' and its subclasses.
error TS2540: Cannot assign to 'id' because it is a read-only property.

2.10 Basic Generics

Generics use a type placeholder, usually T. The same function or type then works with many types and stays type-safe.

function first<T>(items: T[]): T {
  return items[0];
}
console.log(first<number>([10, 20]));  // 10
console.log(first(["a", "b"]));        // a  (T is inferred as string)

interface ApiResponse<T> {
  status: number;
  data: T;
}
const res: ApiResponse<{ name: string }> = { status: 200, data: { name: "Amit" } };
console.log(res.data.name);            // Amit

2.11 tsconfig.json

tsconfig.json holds the compiler settings for the project. Running npx tsc with no file name uses it.

{
  "compilerOptions": {
    "target": "ES2022",
    "module": "commonjs",
    "strict": true,
    "outDir": "dist",
    "rootDir": "src"
  },
  "include": ["src"]
}

target is the JS version to output. module is the module system. strict turns on all strict checks. outDir is where the .js files go. rootDir and include tell which .ts files to compile.

3. Interview Questions and Answers

Q1. What is TypeScript and how is it different from JavaScript?

TypeScript is a superset of JavaScript. This means all JavaScript code is valid TypeScript, and TypeScript adds static types on top. Static types are types checked before the code runs.

JavaScript finds type mistakes only at runtime, often in the middle of a test run. TypeScript finds them at compile time. TypeScript cannot run directly in browsers. It is first compiled into plain JavaScript.

Q2. Why is TypeScript popular in test automation?

It catches mistakes early, like a wrong parameter type, a missing argument or a misspelled property, before the tests even start.

Editors also give better auto-complete for page objects and API responses, and renaming code is safer. In big frameworks with many people, types act like clear documentation of what each function expects.

Q3. What is tsc?

tsc is the TypeScript compiler. It checks the types and turns .ts files into .js files. It is installed with npm install -D typescript and run with npx tsc.

By default, it still writes the .js files even if there are type errors. npx tsc --noEmit only checks types without creating any files, which is common in CI pipelines.

Q4. What is tsconfig.json?

tsconfig.json is the settings file for the TypeScript compiler. It is created with npx tsc --init, and npx tsc uses it when no file name is given.

Important options are target (output JS version), module (module system), strict (strict checks), outDir (output folder), and include (which files to compile).

Q5. What does "strict": true do?

"strict": true turns on a group of strict checks at once. Two important ones are noImplicitAny and strictNullChecks.

noImplicitAny gives an error when a parameter has no type, like error TS7006: Parameter 'a' implicitly has an 'any' type. strictNullChecks forces checks for null and undefined before use. Strict mode is recommended for new projects.

Q6. What are type annotations and type inference?

A type annotation is a type written by hand after a colon, like let age: number = 25.

Type inference means TypeScript guesses the type from the value. For let course = "TypeScript", it knows course is a string. Annotations are mostly needed for function parameters, and inference is fine for simple variables.

Q7. What is the difference between any and unknown?

any switches off type checking fully. Anything can be done with it, so errors appear only at runtime. It removes the main benefit of TypeScript.

unknown also accepts any value, but it cannot be used until its type is checked, for example with typeof value === "string". So unknown is the safe choice for data whose type is not known, like a parsed API response.

Q8. What is a union type?

A union type allows a value to be one of several types, written with |. For example, string | number accepts both a string and a number.

Unions of fixed values are very useful, like type Status = "pass" | "fail" | "skip". Any other string, like "passed", gives a tsc error, which stops typing mistakes.

Q9. What are optional parameters?

An optional parameter has a ? after its name, like title?: string. The function can be called without it, and its value is then undefined.

Optional parameters must come after required ones. Inside the function, the value must be checked before use, otherwise strict mode gives error TS18048: 'title' is possibly 'undefined'.

Q10. What is the difference between type and interface?

Both can describe the shape of an object. An interface is only for object shapes, and it can be extended with extends. Two interfaces with the same name are merged into one.

A type can describe objects and also unions, like "pass" | "fail". Declaring the same type name twice gives error TS2300: Duplicate identifier. Many teams use interface for objects and type for unions.

Q11. What is an enum?

An enum is a named group of fixed values, like roles or environments. Numeric enums start at 0 and go up by 1. String enums give each member a fixed text, like QA = "qa".

Unlike most TypeScript types, an enum exists at runtime as a real JavaScript object. A numeric enum also supports reverse lookup, so Role[1] gives "Tester". String enums are often preferred because their values are clear in logs.

Q12. What are access modifiers?

public members can be used anywhere, and this is the default. private members can be used only inside the same class. protected members can be used inside the class and its child classes.

readonly makes a property unchangeable after it is first set. These are checked only by tsc. After compiling, the JavaScript output has no such protection, unlike JavaScript # private fields.

Q13. What are generics?

Generics let a function, class or type work with many types while keeping type safety. A placeholder like T stands for the type, and it is filled in when used.

For example, ApiResponse<User> and ApiResponse<Product[]> can share one interface, but each knows the exact type of data. Without generics, any would be used, and type checks would be lost.

Q14. Are TypeScript types available at runtime?

No. Types are removed when TypeScript is compiled to JavaScript. This is called type erasure. So typeof at runtime only shows JavaScript types like "string" or "object", never an interface name.

This means data from outside, like API responses or JSON files, is not checked automatically at runtime. Enums and classes are exceptions, because they create real JavaScript code.

Q15. What is a common tsc error and how is it read?

The most common one is error TS2322: Type 'string' is not assignable to type 'number'. It means a value of one type is given to a variable of a different type.

Each error has a code, like TS2322, plus the file name, line and column. Other common ones are TS2345 for a wrong argument type, TS2554 for a wrong number of arguments, and TS2339 for a property that does not exist on a type.

Q16. What does tsc report for this code?

type Status = "pass" | "fail" | "skip";

let result: Status = "pass";
result = "passed";

let count: number = 10;
count = "ten";

Output (tsc)

error TS2820: Type '"passed"' is not assignable to type 'Status'. Did you mean '"pass"'?
error TS2322: Type 'string' is not assignable to type 'number'.

Status only allows the three exact strings. "passed" is not one of them, so tsc shows the exact text in double quotes inside the message.

count is a number, so assigning a string gives the same error code, TS2322, with the general type 'string'.

Q17. What is the output of this enum code?

enum Priority {
  Low = 5,
  Medium,
  High = 10,
  Critical,
}
console.log(Priority.Medium, Priority.Critical);

Output

6 11

In a numeric enum, a member without a value takes the previous value plus 1. Low is 5, so Medium becomes 6.

High is set to 10, so Critical becomes 11.

Q18. What is the output of Object.keys on these enums?

enum Role { Admin, Tester }
enum Env { QA = "qa", Prod = "prod" }

console.log(Object.keys(Role));
console.log(Object.keys(Env));

Output

[ '0', '1', 'Admin', 'Tester' ]
[ 'QA', 'Prod' ]

A numeric enum creates a two-way object. It maps names to numbers and numbers back to names, so the keys include both '0', '1' and 'Admin', 'Tester'.

A string enum creates only a one-way object from names to values, so only 'QA' and 'Prod' appear.

Q19. What does tsc report, and what happens at runtime, for this code?

let data: any = 42;
let value: unknown = 42;

console.log(data.toUpperCase());
console.log(value.toUpperCase());

Output

tsc:     error TS18046: 'value' is of type 'unknown'.
runtime: TypeError: data.toUpperCase is not a function

With any, tsc does not check anything, so no compile error is shown for data. But 42 is a number, so the code crashes at runtime.

With unknown, tsc blocks the call until the type is checked. Since tsc still writes the .js file by default, running it crashes at the first line with the TypeError.

Q20. What does tsc report, and what is printed if the JS output is run anyway?

class Account {
  private balance: number = 500;
}
const acc = new Account();
console.log(acc.balance);

Output

tsc:     error TS2341: Property 'balance' is private and only accessible within class 'Account'.
runtime: 500

tsc blocks access to a private member from outside the class, so it reports TS2341.

But private is only a compile-time check. In the JavaScript output, balance is a normal property, so running it prints 500. For real runtime privacy, JavaScript # private fields are used.
